# UI 设计系统与验收规则

本文件是乐子乌前端视觉规范的唯一真源。改动 `apps/dsa-web/`、登录页或独立构建页面前先读这里。

令牌文件：`apps/dsa-web/src/styles/design-tokens.css`。页面与组件只允许引用 `var(--*)`，不得新写十六进制色值、`rgb()`/`hsl()` 字面量或非阶梯数值。

## 1. 设计定位

暗色专业终端 + 数据密度优先 + 单一品牌强调色。参照 Bloomberg / Linear 的冷静克制，不用消费级圆润活泼。

三条不可妥协：

1. 可读性优先于密度：中文正文最小 12px，手机端正文 16px。
2. 一个语义只有一个视觉表达：主操作用品牌橙，涨跌用红绿，图表用图表色板，三者互不串用。
3. 删字腾空间，而不是缩字腾空间。

## 2. 颜色

| 组 | 令牌 | 用途 |
| --- | --- | --- |
| 品牌 | `--brand` `--brand-hover` `--brand-pressed` `--brand-text` `--brand-on` `--brand-tint-08/16` | 主按钮、当前导航指示、聚焦环、关键数字高亮。禁止用于涨跌、图表线 |
| 中性 | `--bg-0..3` `--line-1/2` `--text-1..4` | 页面底 / 卡片 / 输入框 / 悬浮层；分隔线与描边；四级文字 |
| 金融语义 | `--up` `--down` `--flat` `-bg` | 只用于数字、涨跌 tag、迷你走势线 |
| 状态 | `--success/-warning/-danger/-info` 各配 `-bg`(12%) `-border`(32%) | 系统状态，不再派生其他明度 |
| 图表 | `--chart-1..5` | 多序列按序号取色；单序列用 `--chart-1`；不得用品牌橙 |

对比度下限（已实测）：深色 `--text-2` 对 `--bg-1` 8.9:1、`--text-3` 5.3:1；浅色 9.7:1 / 5.6:1。

两套主题共用同一组令牌名：`:root` 为浅色、`.dark` 为深色，差异只在 `design-tokens.css`。禁止再为某个页面单独 fork 一套主题变量。

## 3. 字体

字体栈：`Inter, "PingFang SC", "MiSans", "HarmonyOS Sans SC", "Microsoft YaHei", system-ui, sans-serif`。Inter 为自托管 woff2（`src/assets/fonts/`，latin 子集，`font-display: swap`）。

| 令牌 | 网页端 | 手机端 | 用途 |
| --- | --- | --- | --- |
| `--fs-display` | 32/40 700 | 32/40 700 | 指数点位主数字 |
| `--fs-h1` | 24/32 600 | 20/28 600 | 页面主标题，每页 1 个 |
| `--fs-h2` | 18/26 600 | 16/24 600 | 卡片标题 |
| `--fs-h3` | 15/22 600 | 16/24 600 | 区块小标题、表头 |
| `--fs-body` | 14/22 400 | 16/24 400 | 正文、导航 |
| `--fs-sm` | 13/20 400 | 14/21 400 | 次要列、密集列表 |
| `--fs-caption` | 12/18 400 | 12/18 400 | 时间戳、来源、角标（全站最小） |
| `--fs-num-lg` | 22/28 700 | 20/28 700 | 卡片主数值 |
| `--fs-num` | 15/22 600 | 16/24 600 | 行内数值 |

字重只有 400 / 500 / 600 / 700。禁止 650、550、`bolder`（中文字体无该字面，浏览器合成为假粗）。行高一律取令牌固定 px，禁用比例写法。数值一律 `font-variant-numeric: tabular-nums`。

## 4. 间距、圆角与控件

间距阶梯只有 `4/8/12/16/24/32/48/64`（`--gap-2xs..2xl`、`--page-x`）。圆角只有 `4/8/12/9999`（`--radius-tag/control/card/pill`）。控件高度只有 `28/32/36/44`（`--h-sm..xl`）。卡片内边距 16 或 20，卡片之间 16。阴影只有 `--shadow-card` 与 `--shadow-pop`，暗色下不用外发光。

表格：行高紧凑 32 / 舒适 40，单元格左右内边距 12，数字列右对齐且 tabular-nums，表头 `--fs-h3`，表体不小于 13px。

## 5. 布局与断点

- 桌面：侧栏 240px（折叠 64px，`sticky` `100dvh`）+ 主内容 `min-width: 0`，内容最大宽 1680 居中。
- 断点只有 4 个：`480 / 768 / 1024 / 1440`。
- 视口单位一律 `dvh`/`svh`，禁止 `100vh`。
- `overflow: hidden` 只允许出现在头像裁剪、图表 canvas、加载遮罩三处。
- 图表容器尺寸变化必须重绘（`ResizeObserver`）。

手机端只有一套导航：底部 4 个高频入口（总览 / 自选 / 会议 / 题材）+「更多」（全量模块列表）。当前页面必须能在底部栏高亮；不属于前 4 项时「更多」高亮。触控热区不小于 44×44（视觉尺寸可小，用伪元素扩展）。

## 6. 组件规则

- 按钮只有 4 种：`primary`（品牌实心）、`secondary`（透明底 + 描边）、`ghost`（无底无边）、`danger`。全屏只允许 1 个 primary。
- Tab 只有一种：下划线式（选中 `--text-1` + 2px `--brand` 下划线）。同一容器内不得出现第二种选中态。
- Tag 只有 3 种：status（语义色浅底 + 语义色字）、neutral、brand。
- 输入框高 36（手机 44）、圆角 8、底 `--bg-2`、描边 `--line-2`、聚焦品牌描边 + 焦点环；placeholder 用 `--text-3`。
- 卡片头固定结构：`[18px 图标] 标题 + 可选 status tag + 右侧最多 1 个文字链接 + 1 个图标按钮`。
- 侧栏导航项：高 40、左右内边距 12、图标固定 18px 槽位、左对齐，选中态只有一种（`--bg-3` 底 + 左侧 3px 品牌竖条 + `--text-1`）。
- 图标只用 Lucide，`stroke-width` 1.5–2，三档尺寸 16 / 18 / 24；图标按钮必须带 `aria-label`。

## 7. 文案与状态

- 每张卡片最多 1 行 12px 说明；每屏最多 3 处。
- 免责声明全站恰好 1 处：数据页脚「数据仅供参考，不构成投资建议」。
- 禁止口号式副标题、复述型提示、技术泄漏（`SQLite`、适配器名、`tensoft.xxx` 这类标识）、每张卡重复的署名、按钮旁提示。
- 状态四件套：空态（一句话说明为什么空 + 1 个主行动）、加载态（骨架屏，不用居中转圈）、错误态（说清哪一步失败 + 重试 + 折叠错误码）、局部降级（单卡显示「数据缺失」，不整屏白屏）。
- 语气：短句、动词开头、给数字；禁止「欢迎使用」「让我们一起」「正在努力」「亲爱的用户」等句式。

## 8. 验收

改了页面/组件后，用下面三项核对（`apps/dsa-web` 目录下）：

```bash
npm run lint
npm run build
npx vitest run --maxWorkers=2
```

浏览器侧逐条量（同一份脚本对每个路由跑一次，深/浅两套主题都要跑）：

- `document.documentElement.scrollWidth === innerWidth`（无页面级横向滚动）。
- 被 `overflow: hidden` 祖先裁掉的可见内容 = 0。
- `font-size < 12px` 的可见文本节点 = 0。
- 手机端可点热区 ≥ 44×44。
- 颜色/字号/圆角取值集合 ⊆ 本文件令牌集合。

审计脚本实现与每轮实测数据在 `.claude/reviews/ui-refresh-20261109/`（本地产物，不入库）。

## 9. 手机端应用外壳

手机端（≤1023px）不是把桌面页缩小，而是独立的一套壳与组件。实现在 `src/styles/mobile-app.css` 与 `src/components/mobile/`。

### 壳层结构

```
MobileAppBar（sticky，44px 行 + 文档流大标题）
  └ 主内容 .mobile-shell-main（底部留出 56px + 安全区）
MobileBottomNav（fixed，5 项：团队 · 行情 · 自选 · 总览 · 更多）
```

- 大标题在文档流里、随内容滚走；应用栏滚过 32px 后收起为单行标题，避免固定大标题占掉首屏。
- 二级页面（路径有第二段，或浏览器历史可后退）显示返回箭头，标题直接用小号。
- 底部标签栏是手机端唯一导航。当前页不在前 4 项时「更多」高亮，保证始终有高亮项。
- 「更多」是全屏底部弹层里的模块宫格（与侧栏共用 `navItems.ts` 的同一份清单），末尾是外观与语言切换。
- 全站 `viewport-fit=cover`；上下留白用 `env(safe-area-inset-*)`。

### 手机端专用组件

| 组件 | 用途 |
| --- | --- |
| `MobileAppBar` | 应用栏；大标题收起、返回、最多 2 个图标动作 + 溢出菜单 |
| `BottomSheet` | 底部弹层：把手、固定标题栏、单一滚动体、可选固定动作区；下滑或点遮罩关闭 |
| `SegmentedChips` | 页内视图切换（横向 chips，选中品牌描边） |
| `MobileListRow` / `MobileGroup` | 列表行与分组卡：日期、价格、涨跌走的都是这套行 |
| `MobileSkeleton` | 形状与真实内容一致的骨架屏 |
| `MobileHome` | 「行情」页手机版：指数主卡 + 迷你走势 + 自选 + 广度 + 行业 + 快讯 + 快捷入口 |
| `MobileMoreSheet` | 「更多」：弹层里的模块宫格 + 外观/语言 |

### 页面级约定

- 表格在手机上不横向滚动，降级成 `MobileListRow`。
- 桌面端多列面板在手机上单列、间距 16，页面左右内边距 16。
- 「总览」是个人工作台（`/home`），「行情」是市场数据（`/app`）；两者不重复。
- 列表页（如「自选」）在手机上先列表、点进详情，不默认选中第一只股票。
- 「任务中心」在手机上：桌面端 hero 标题隐藏（应用栏已有标题）、统计 2×2、入口 2×2、类型筛选用 chips、任务行纵向排。
- 页面自己的横向滚动区（统计条、chips）用 `margin-inline: -16px; padding-inline: 16px` 做通栏，不要把页面 padding 归零。

## 10. 页面内容预算（硬规则）

单页信息过载是当前最突出的问题：`SettingsPage` 1736 行、`PortfolioPage` 1734 行、`ChatPage` 1719 行，用户在一个屏幕上被塞了本该分 3～4 屏的内容。层级可以多，但**一屏只讲一件事**。

按屏计（桌面 1440×900，扣掉侧栏与应用栏后约 1.5 屏内容高度）：

| 预算项 | 上限 |
| --- | --- |
| 一级区块（卡片/面板） | 6 个 |
| 首屏可见的一级区块 | 4 个 |
| 单页表格行（不含分页） | 25 行 |
| 单页并列指标卡 | 8 个 |
| 单页说明性文字 | 3 处 × 1 行 |

超过即必须切分，不许靠缩字号、缩行高硬塞。切分优先级：

1. **主 Tab**（同一路由内，下划线式，2～5 个）：把互斥的视图拆开，默认只渲染当前 Tab。
2. **子 Tab / 分段控件**：主 Tab 内再分，最多 2 层，不得出现第 3 层。
3. **抽屉 / 弹层**：详情、原始记录、二次操作走抽屉，不占页面纵向空间。
4. **独立路由**：低频但完整的流程（设置、回测、导入）拆成子路由，用侧栏二级项进入。

禁止：用折叠面板（`Collapsible`）无限堆长页面。折叠只用于「默认不需要看、但需要能就地展开」的补充说明，同页不超过 3 个。

Tab 切换必须：只挂载当前 Tab 内容（不靠 CSS 隐藏全部）、记住选中 Tab（写 URL query 或记忆）、切 Tab 时滚回内容顶部。

## 11. 数字与可视化

数据页的说服力来自数字排版和图形编码，不来自彩色卡片。当前多数模块只有纯文本表格，这是要补的重点。

**数字排版**
- 所有数字列 `font-variant-numeric: tabular-nums` 且右对齐；百分比、金额、增减量同规则。
- 三级层次固定：主数字 `--fs-h2` 600 → 变化量 `--fs-body` 500 带涨跌色 → 辅助说明 `--fs-caption` `--text-3`。同一区块内不得出现第四级。
- 颜色只表达涨跌与状态，不表达重要性；重要性用字号和位置表达。
- 空值统一显示 `—`（`--text-4`），禁止 `0`、`N/A`、`null`、空白。

**行内可视化（优先于独立图表）**
图表是列表的一列，不是单独一块。以下四种必须在相关列表中出现：

| 组件 | 用途 | 规格 |
| --- | --- | --- |
| `Sparkline` | 时序趋势（价格、关注度、资金流） | 高 16～20px，线宽 1.2，面积填充 ≤0.12，不画坐标轴 |
| `BarMeter` | 规模对比（营收、市值、成交额）；有符号数据（涨跌幅）传 `baseline="center"` | 行内横条，高 3～4px，长度∝值，超出上限做对数压缩；`center` 基线以中线为零轴、负值向左生长并自动用跌色 |
| `ShareBar` | 构成占比（多空、行业分布） | 单条 3px 堆叠条，段间不留缝，最多 5 段 |
| `HeatCell` | 密度/强度分布 | 小方格矩阵，色阶只用涨跌色 4 档透明度 |

**独立图表语言**
- 线宽 1.2～1.4，`strokeLinecap="round"`，面积 `fillOpacity ≤ 0.12`。
- 网格线 `--line-1`，零轴 `--line-2`，刻度 `--fs-caption` `--text-3`；**不画图例框**，用端点标签 + 涨跌色代替。
- 任何色块 `fill-opacity ≤ 0.25` 且加 1px 同色 40% 描边；**禁止 100% 不透明大面积平涂**。
- 单序列用 `--chart-1`，多序列按 `--chart-1..5` 顺序取色，不得用品牌橙表示数据。

**统计入标题栏**
区块级统计（合计、涨跌家数、今日新增）放进卡片头的右侧 meta 位，不要单独占一行统计条；统计条与明细表达同一批数据是重复。

## 12. 收紧与减法

- 卡片内边距：`--gap-md`(12) 为基准，禁止一律 16/24；嵌套卡片禁止（卡片里不要再套卡片，用 1px `--line-1` 分割 + 小标题）。
- 区块间距：同级 `--gap-lg`(16)，跨级 `--gap-xl`(24)；禁止处处 24 造成的松散感。
- 卡片圆角统一 `--radius-card`(12)；内部元素 `--radius-control`(8)；不要每个元素都圆角。
- 阴影只允许出现在浮层（下拉、抽屉、弹层）；页面内卡片一律不投影，靠描边与底色分层。
- 表格行高：密集列表 32，仅详情表用 40；禁止 44+ 的行高。
- 去掉装饰性元素：无意义的渐变、粒子背景、发光、粗描边、图标底衬色块。

**行高与字距（§12 补充，2026-11-14）**
- 行高一律用 `--lh-*` 令牌，不得在页面 CSS 里写裸数字。数据行/表格行 ≤1.4 倍字号；正文 1.5～1.6；只有长文阅读面（使用指南、报告正文）允许到 1.7。
- 字距（`letter-spacing`）只允许 `--tracking-*` 或 0；页面 CSS 自定义字距视为违规。中文正文不需要正字距，数字列也不需要负字距。
- 现状：全站有 40 处 `line-height: 1.7`、18 处 `1.8`、11 处 `1.75` 散落在页面 CSS，是「松散网页感」的主要来源之一，应逐步收敛到令牌。

## 13. 反「AI 味」禁用清单

以下模式一律禁止，出现在代码评审中视为不合格：

1. 三等分卡片网格铺满整屏（`grid-cols-3` 同尺寸卡片超过 6 个）。
2. 所有元素同一内边距、同一圆角、同一间距的「均匀感」。
3. 紫蓝渐变、霓虹发光、玻璃拟态（除非有明确功能理由并注释说明）。
4. emoji 当图标。
5. 每张卡片都配副标题、都配图标、都配说明文字。
6. 居中大标题 + 副标题 + 渐变背景的「落地页式」区块出现在数据页。
7. 大面积纯色平涂色块（见 §11）。
8. 装饰性动画：无状态含义的浮动、呼吸、旋转。
9. 空态里放插画占位。
10. 重复表达同一数据的统计条 + 明细。

## 14. 重构落地顺序

改页面时按此顺序，避免只改样式不改结构：

1. 先按 §10 做**信息架构切分**（拆 Tab / 拆路由 / 移抽屉），确定这一屏只讲什么。
2. 再按 §11 决定**用什么可视化**表达数据（列内 sparkline / 条形 / 占比条）。
3. 再按 §12 收紧**间距与层级**。
4. 最后按 §13 自查**反 AI 味**。
5. 跑 §8 验收命令与浏览器侧检查。

## 15. 手机端对话界面（AI 会话）

手机端对话是使用频率最高的界面，单独设计，不沿用桌面排版。基准来自 ChatGPT 移动端与
[GAIA Mobile Chat Standards](https://github.com/theexperiencecompany/gaia/blob/93fc2db44f59b9939b1650f694462bbd03d8348e/apps/mobile/CHAT_STANDARDS.md)。

**结构纪律**

| 项 | 手机端 | 桌面端 |
| --- | --- | --- |
| 用户消息 | 右侧气泡，`--bg-3` 浅底，圆角 16，**max-width 82%** | 同（可用 72%） |
| **AI 消息** | **无气泡、无边框、无背景**，文本直接铺页面底色，**全宽可读** | 可保留气泡 |
| 头像 | **不显示** | 可显示 32px |
| 角色标签 | **每条消息上方不显示**；整段会话只在顶部出现一次 | 同 |
| 消息区左右内边距 | 16px | 16～24px |
| 正文字号 / 行高 | 13.5～14px / 1.5～1.55 | 14～15px / 1.55 |
| 消息间距 | 跨角色 16px；同角色连续 6px | 同 |
| 输入框 | 高 40，字号 14，发送按钮 34 | 高 44 |

**为什么 AI 消息不用气泡**：长回答、表格、代码需要整列宽度；气泡会把可读宽度压到 60% 以下，
并且在移动端制造大量无意义的圆角与描边。业界主流（ChatGPT / Claude / Gemini）全部采用
「用户气泡 + AI 平铺」的双轨，而不是两边都套气泡。

**禁止**：每条消息重复显示助手名称、每条消息配头像、气泡内再套卡片、给 AI 消息加阴影或渐变。

**断点**：对话相关样式统一使用 `max-width: 1023px`（与 `hooks/useIsMobile.ts` 一致），
`<768px` 再收紧一档。历史上 chat 手机样式只写在 640px，导致 641–1023 区间拿到手机逻辑却配桌面样式。
