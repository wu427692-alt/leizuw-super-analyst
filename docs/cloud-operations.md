# 乐子乌超级价值：2 核 4 GB 云端运行基线

本文记录当前阿里云轻量服务器的生产运行边界，目标是在不裁剪业务功能的前提下，降低启动峰值、常驻内存、重复请求和磁盘膨胀。

## 服务分工

- `stock-server`：网页、API、用户任务和本地 SQLite 查询，资源上限 1.75 CPU / 2200 MB。
- `stock-monitor-worker`：公告、新闻、股评、知识星球等增量监控，串行拉取，资源上限 0.40 CPU / 900 MB。
- Nginx：TLS 入口、静态资源缓存和反向代理。
- systemd 可用性守卫：每 30 秒检查健康状态；启动期不误杀，连续三次失败才重启网页容器。

## 资源策略

- 启动只预热首屏所需的索引查询；90/180 日洞察、行业蓝图等重任务按需计算并缓存。
- SQLite 使用 WAL、小页缓存和短事务；列表查询不加载大体积原始载荷。
- 洞察缓存设置条目上限和 TTL，淘汰只触发重新计算，不删除数据库内容。
- 前端任务轮询仅在页面可见时高频运行，隐藏标签页自动降频。
- 生产不重复写 DEBUG 文件；常规日志轮转并清理超过 14 天的文件。

## 发布与回滚

1. 发布前运行后端与前端完整测试，并校验 Compose 配置。
2. 停止可用性守卫定时器，构建新镜像；数据库、日志、报告和配置均使用宿主机挂载，不进入镜像。
3. 仅重建网页与监控容器，等待健康检查通过后恢复守卫。
4. 检查公开首页、登录拦截、健康接口、容器内存和最近错误日志。
5. 如验证失败，使用上一镜像重建容器；数据卷不回滚、不丢失。

## 日常检查

- 磁盘：数据库、日志、Docker 镜像与构建缓存分别统计，磁盘达到 80% 前清理可重新生成的旧构建缓存。
- 内存：以容器常驻内存和系统可用内存为准；Swap 仅用于短峰值，不作为正常容量。
- 数据：检查行情、知识星球、巨潮公告和投资情报的最近成功时间；未配置渠道进入长退避，不做无效高频重试。
- 可用性：确认两个容器运行、网页容器健康、守卫定时器为 active。
