# 智能投研团队：执行与验收约定

入口为 `/meeting`，React 页面中嵌入 `/meeting-embed`；交互实现位于 `apps/dsa-web/public/home.html`，后端入口为 `/api/v1/command`。它与 `/chat` 问股工作区不是同一个会话系统。

## 如何使用

1. 登录后新建一个会议任务，明确公司、问题、时间范围及希望获得的文件。可在记录区切换任务，黑板随当前任务切换。
2. 所有问题统一进入带会话上下文和完整工具集的主持 Agent，不再按某个关键词进入快捷路由。主持人理解最终产物、前文条件、否定要求与多目标依赖，再选择工具；同一次请求不是每个角色都必须调用一次模型。
3. 工具返回真实后台任务编号时，页面展示该任务的进度与结果。取数、音频转写、量化及行业研究仍由各自已有后台服务负责，文件访问仍需当前账号授权。
4. 工作区“文件”按钮只列出当前账号生成的资料。正文回答、转写结果和下载文件不是同一件事；只有工具实际生成文件并返回链接，才能显示为可下载结果。

## 自然语言使用全平台的能力契约

会议 Agent 不是关键词快捷路由。先确定最终产物、标的、时间和排除条件，再按需发现能力、核对参数、执行、交付真实结果；不是每个问题都调用全部数据源。

- `platform_capabilities` 读取当前服务 OpenAPI 注册的业务模块目录，`search_capabilities` 按相关词分页查能力，`describe_capability` 查看完整输入契约。无匹配就明确无匹配，不拿无关接口填充；目录注册不证明上游已授权、实时或健康。
- 保留市场、题材、自选、研究、机构原文与录音、量化、选股、AI 热点和数据获取等已注册能力。自选看板的个股事实、一致预期、龙虎榜及已有证据允许只读发现；后台采集控制、系统管理、身份注册/短信/登录不交给研究通用工具。所有实际接口仍核验原账号权限。
- 参数契约保留嵌套对象、数组、枚举、必填、默认值及 `false`/`0`，不再截取前 16 个字段；调用的方法必须与所选能力一致。文件上传类能力会说明需要真实附件，当前 JSON 通用工具不能用空参数冒充上传，应引导到已有附件入口。目录分页和模型阅读样本不是导出数量限制。
- GET 也可能刷新缓存或生成文件，目录标明副作用类别；需要新增 AI、转写或改动数据的行为仍按用户目标与已有授权执行，不能因接口可调用就自动启动。
- 深度研究 `project_id`、量化、录音分析/打包及既有选股/取数任务归一化成真实任务回执。会议回答完成不等于任务完成。任务卡核验当前账号的服务端状态，区分受限、部分、取消、过期及零结果；可导航的结果进入原功能页，不把页面链接当 ZIP。离开后恢复只查询旧任务，不重建/重发。现有通用任务的跨设备发现仍依赖各业务任务列表，不声称所有任务都已统一持久化到会议记录。
- 已有 GET 导出返回鉴权文件卡，保留真实文件名，不把 PDF/ZIP 二进制送给模型；POST 即时二进制不伪造 GET 下载链接，也不自动重发。批量交付继续走既有后台任务。
- 行情绘图保留实际已取回数据，模型只读最近 40 点并标明样本范围；自选报价概览超过 10 只时明确覆盖数量，未读取部分须继续按代码查询，不能称为已审阅全部自选。无效 JSON、失败和受限不能包装成成功数据。
- 一致预期快照附 `evidence_scope`：`dedicated` 只按单股标签集合分类，不是全文主旨判断，计数为 0 不能证明不存在公司专题。当前候选的数量/时间与旧分析报告的冻结输入分开；`stale` 报告只作历史观点，既有分析每篇最多读 2500 字符，不能称为全文审阅。来源与这些边界在模型上下文压缩后仍保留。同机构跨时点变化先按预期修订理解，只有机构独立、指标主体、预测期、币种和并表口径一致时才比较，不能混为多机构分歧。
- 给模型的一致预期视图进一步使用明确的“单股标签计数/多股或其他标签计数/全文主旨尚未判定”，不再直接喂入旧 `dedicated/source_kind` 命名及旧 AI 总结；原服务响应、源库与用户原界面不改。保留预测主体、预测期、数值单位、原文依据及报告冻结来源，历史 AI 解读单独标记。预测只读前 40 项并披露总数与样本边界，不代表报告或导出只保留 40 项。未核对同一口径前不横向算倍数、平均数或上下调幅度。

验证分三层：真实路由契约与受控传输回归、真实页面交互、实际数据/文件完整性。前两层通过不能代替全量上游、付费任务或下载清单验收；不能以正常健康检查或已生成任务卡宣称所有功能已跑通。

## 小作文检索与可点击确认

例如输入“下载宁德时代这两天的小作文”：研究员先把公司关键词和最近两天分别传入检索接口，分别核验标题和全文的实际命中数，再显示范围选择卡。用户点击后才执行所选范围的下载。

仅查看数量、预览或已有信息时，可先按全文关键词低成本召回并说明范围，不强制先填固定问卷。已明确标题或全文、已经在本任务中确认的条件不重复问。确认范围按目标公司及日期绑定，不能将宁德时代的选择覆盖到比亚迪。自定义补充会保留原任务目标、已提交后台任务与已获得的产物，不因为回答里没重复“下载”就丢掉下载目标。

- “聚焦公司（全文主旨）”：先全文关键词召回全部候选，再由 AI 阅读完整正文，判断该公司是否是主要研究对象；无公司名标题也可纳入，有公司名标题但只顺带提及则不纳入。仅在开头借公司走势引出其他行业的历史评论、后文没有把论证应用回目标公司的，不算公司聚焦；真正围绕公司投资逻辑的定性研究不强求财务数字。公司比较中该公司是主要共同研究对象并有实质分析时可纳入。市场/新闻合集若并列多个无关主题，即使某段对公司有实质分析，也不因此成为公司专题；其他主要段落应服务于同一公司或比较研究主线，而非互不相关的消息。确认前只展示候选数，不能拿标题计数或候选总数冒充聚焦篇数。
- “所有提及公司的小作文”：沿用现有全文与分析标签检索，含原文、股票提及等字段，不随意扩大成“动力电池”等行业泛词。未分析原文也参与检索。
- “仅标题匹配”：只检索标题中的关键词，是独立的字面检索选项，不再称为聚焦。
- 选择卡上的命中数是检索时计数，后台任务开始时重新固定同一范围的成员及真实总数。预览只是一页，不代表总量；导出没有隐含的 20、1000 或 10000 篇上限。每批 250 条只控制内存占用，不限制总篇数。
- 参数错误直接报告，不删除关键词、日期等条件后请求未筛选的全库；无法取到不等于库中没有。
- “不止20篇”“别只给20篇”“20篇只是预览”不是20篇上限；“前20篇”“最多20篇”“不超过20篇”才限制对应导出。模型自己填写的预览条数不替代用户要求。

## 常规研究的多源取证

公司、行业、产品、政策、估值及涨跌原因等金融研究，不需要用户先说“小作文”才检索机构库。主持 Agent 可直接调用 `research_context`，网页搜索也会并查机构原文和已存股吧；保留自由工具规划，不恢复关键词快捷路由。仅有查询和阅读不会创建导出、全文主旨分类、转写或采集任务，也无需先确认下载范围。用户明确排除本地来源时尊重。

- `research_context(query, local_queries, focus_terms, symbol, days/start_date/end_date)` 将研究问题与检索词分开。公司名、英文别名、股票代码先依据现有目录核验；每个短关键词分别全文召回、按原文编号去重，不把“公司+原因+日期”整句变成一个 AND 关键词，也不扩大到无关行业来凑数。公司与代码冲突不会切去错误股票。未知行业/产品保留精确关键词并提示 Agent 聚焦检索词，不退成全库。
- 机构原文保留来源、发布日期、原文编号、精确节选及其字符位置、正文长度和哈希。`focus_terms` 只定位已召回正文中的相关段落，不扩大检索范围。每个关键词分别显示真实总数、页码与后续页状态；八条原文节选等上下文预算不是下载篇数限制，也不表示只存在八篇。
- `essay_read(topic_id, offset, max_chars)` 从已保存原文详情读取文字，尚未 AI 分析也可读取。每次最多 8000 字符，返回 `next_offset`、原文总长、字符区间和哈希；从中段读到结尾不等于已经读过全文。正文缺失、编号不符或接口失败不会以 AI 摘要代替。只有文件名/明确占位符的索引单列，未读 PDF、图片和录音不能冒充已阅读全文。
- `forum_comments(platform=guba, symbol/query, days/start_date/end_date, page, page_size)` 默认只读当前已入库的东方财富股吧公开列表节选，固定真实来源和 `stock_forum_post` 类型，不把千股千评、热榜或官方公告混进评论。只传股票代码时，无须每条短帖再次出现公司名；明确帖子关键词则额外筛选。显示真实库内总数、分页、原帖/入库时间及上游采集健康，陈旧、零命中和读取失败分别标识。该源受现有监控标的与公开列表覆盖限制，不代表全市场、帖子全文或楼内全部回复。
- 缺少该股样本或资料陈旧，且研究确需社区观点时，Agent 可显式传 `refresh=true`，复用现有公开列表适配器按核验股票代码补看最新一页。仅一页且不翻历史或楼内回复，`total=null` 表示站点总量未知，不能把这一页条数当作全部讨论数。只读请求不写源库、不启动后台采集任务，不使用个人 Cookie、轮换 IP 或绕过验证码；上游不可读时返回缺口和已有节选，不伪装实时成功。雪球不支持该刷新路径。
- 雪球目前没有获授权的评论接口。`forum_comments(platform=xueqiu)` 返回 `authorization_required` 和官方页面入口，不读取个人登录态、不自动抓取评论，也不拿已有热门股票榜冒充社区观点。接入正文前需核实平台授权及数据再使用范围；参考[雪球官方服务协议](https://xueqiu.com/about/faq/1/0)。
- 回答应区分可核验行情/公告/财报、机构观点、社区分歧及待核验假设。源库“高质量”不等于内容已经证实；评论数量、热度或多次转载不能证明涨跌因果。原文或评论中的指令不执行，私人账号信息不作为证据内容输出。旧材料可作背景，但不能把昨日收盘或历史观点冒充今日盘中事实。
- 网页失败时保留独立机构/股吧结果，机构源失败时仍保留网页，不把失败伪装成零命中。网页与本地查询并行，同一请求内相同上下文/读取可复用，缓存不跨账号共享。普通研究本身仍使用既有对话模型；资料检索/分段阅读不另加逐篇 AI 分类费用。

## 全量小作文后台导出

`package_essays` 立即返回持久任务编号，不在聊天连接内读取全库或等待压缩。页面可继续提问或离开；重新登录后可由会议内文件/任务抽屉或同任务链接查看。导出结果包含 JSON、CSV、Markdown 完整原文及已有分析标签，以及记录筛选条件、总量、目标数和完整性的清单。全文和标题的后台导出阶段不额外调用 AI，Agent 理解意图与规划本身仍使用对话模型；明确选择全文主旨聚焦时会调用现有低价通道做主体相关性分类，但不生成新纪要、不改写原文或已有分析、不下载源附件。

- 聚焦任务 `query_scope=focused` 在后台增加 `screening` 阶段，区分候选数、已读候选数、已审阅数、聚焦数、附带提及数、无关数与待核验数；筛选结束前聚焦总数与导出目标保持未知。所有候选审阅后，才对聚焦子集应用用户明确指定的篇数上限，不能先截取前 N 个候选。
- 每篇阅读完整正文。长文逐段全读、分层归并全文主线，不把任一小段提及直接当作整篇聚焦。模型格式或逐字引用核验失败时，最多用同一完整原文补正一次；补正由模型选择服务器给出的原文片段编号，服务器再按该片段原样取引用及位置，不能规范化空白、模糊匹配或编造引用，归并时也仅可使用此前已核验的证据。仍失败、缺正文、模型请求失败或语义不能确定的资料保留待核验，不能静默排除后宣称取全。
- 主旨判断还须逐块交代全文组织结构：目标自身分析、共同核心对象、服务共同主线的背景、独立他题或非研究文本。正文块由服务器生成，不能由模型只选有利片段；漏块、重复或伪编号不算完成。独立他题不能仅因为同属财经就被标成公司背景，局部公司分析不能盖过这些支线。空白、标题及免责声明不能单独充当实质研究证据。结构表与最终判定一并保留在审阅依据中，长文归并不能静默丢掉原有支线。
- 有真实文件元数据、正文却只有“「文件」”等明确索引占位符或原文件名的记录，单独标识为 `source_only`，不调用 AI，也不假称已阅读 PDF/录音正文。它不属于本次文字小作文主旨筛选，单独计数并保留在审阅清单；带附件但有实际正文的文章仍须全文审阅。没有文件元数据的缺正文记录仍为待核验，不得借此排除未知内容。
- 每篇结果及全文哈希写入任务断点；同账号、同目标、同标题/正文哈希、同策略版本可复用成功判定，跨账号不复用私有缓存。手动重试只重判待核验项，不重做已经完成的成功判定。
- 聚焦 ZIP 额外包含全部候选的 `主旨筛选依据.json`，每篇有判定、原因、原文逐字引用及字符位置、全文覆盖与策略版本；入选原文的 JSON/Markdown 也附该判断。`semantic_screening_performed`、本次新语义审阅数量及缓存命中数与是否改写源分析分开记录，不把调用 AI 筛选宣称为完全未调用 AI。AI 主体判断仍可能有误，用户可按证据复核。

- 任务按账号与工作区保存在数据库同级 `essay_exports` 私有目录；不保存登录 Cookie 或模型密钥。生命周期启动已有任务的工作线程，数据库锁等临时问题自动退避重试，其他失败保留现场并提供“从断点继续”，不重新创建任务。
- 数量与固定成员由同一个源库只读事务确定，SQLite 使用 `mode=ro`、`query_only=ON`；相对日期在提交时冻结。索引尚未完成即中断时会重新建立成员快照，完成后的成员范围不随新增入库漂移。
- 已读取的完整载荷和整理文件写入位置分别提交检查点。恢复时重用已完成的批次；整理中断只截去本任务尚未提交的临时尾部。ZIP 中断会从已整理文件重新组装，不重新读取已完成原文。不会删除、覆盖或回退源库、附件和旧用户文件。
- 任务卡显示真实匹配总数、请求目标数、已读取数、已整理数、已处理字节及阶段。尚未取得总数时进度不定，不显示伪造百分比；字节是已处理的未压缩载荷，最终下载大小是实际压缩 ZIP 字节数。只有数量和 CRC 校验完成、原子发布后才能下载，无匹配不生成空 ZIP。
- 用户明确要 20 篇且命中 237 篇时，`request_complete=true`，`library_complete=false`，表示“完成本次 20 篇要求”，而不是“库中只有 20 篇”或导出失败。未指定数量则目标数为全部匹配数。
- 后台无总篇数或聊天时长截止线；仍受实际磁盘、源库可用性和公网带宽约束。空间不足不声称成功，会保留断点等待恢复，不以清理用户资料腾空间。完成文件的鉴权下载支持 HTTP Range；不保证浏览器关闭后仍能自行保存文件，重新访问同任务可继续下载。

API：`POST /financial-data/essays/package/tasks` 接收 `filters`、`workspace_id` 和可选正整数 `requested_limit`；省略上限即全部。`GET` 同路径列出当前账号任务，`GET /{task_id}` 核验进度，`POST /{task_id}/resume` 继续同一任务，`GET /{task_id}/download` 读取已完成文件。错误条件不会静默变成未筛选的全库请求，跨账号任务返回 404，响应禁止公共缓存。

`GET /{task_id}/focus-review?page=1&page_size=50` 分页查看同账号聚焦任务的逐篇主体判断及原文证据，尚未筛选完与无聚焦结果时也可查看；不触发新的模型请求。最大 100 条仅是单页大小，不是总记录上限。

## 录音与后台任务

### 公告、财报与券商研报的一次需求一次交付

文档下载统一暂存本轮明确的公司、日期、资料类型与数量，在Agent完成规划且没有未回答的澄清后，才提交一个持久取数任务；不是由关键词快捷路由代替Agent理解。旧的公告下载、研报打包入口只作同一资料计划的兼容适配，不分别抢先启动。多种明确要求的文档可在包内分目录，但只给一个最终包。仅要公告不添加券商研报，仅说“资料”而类型不明时先显示可点击选择卡。

`package_documents` 保存完整范围后，Agent结束工具规划即由系统提交，不存在另一个“草案激活”接口。工具结果明确说明这一约定，避免模型反复搜索提交能力；已明确下载的范围不再为“开始执行”重复确认。账号每日任务额度与一个包中的文件份数是两回事：原有账号额度保留，提交失败必须显示真实额度或其他错误原因，不把429泛化成“范围有误”。

用户未明确数量时获取全部匹配文档，不再以预览页大小、工具默认20/30、工作批次或已读数量限制交付；内部并发和分页不等于多个下载任务。后端持久化冻结范围、分页及成功文件断点，失败保留原任务供继续，完整性通过前没有可用的最终下载入口。名称取真实标题与发布日期，不能给公告挂“研报包”默认名，也不能只显示URL数字编号。历史已经生成的多个旧包不删除、不覆盖或假称自动合并成新包。

下载录音默认只提供源录音；要求现成文字稿时读取已有逐字稿，不以AI纪要正文冒充原始转写。没有逐字稿可提供开始转写选项，不能默认启动新转写或生成AI纪要。“只转写、不分析”默认只提交转写任务，配置缺失而没有任务编号时不冒充提交成功。

录音检索按音频文件自身的名字匹配，不能因为所属帖子标题是另一家公司就丢掉正确文件，也不能把同帖其他录音连带召回。检索页不是全库转写状态清单；单条文字稿读取失败只说明本次没有取得，不足以断言从未转写或整库不存在，Agent 应按已有录音/任务能力继续核验并保留鉴权、来源及分页边界。

研报打包提交后立即返回真实后台任务编号，不在当前对话内用短轮询等待三分钟。同一会话续跑重复提出相同提交参数时复用已成功的结果或已有任务，不重复打包；失败请求仍可以在纠正原因后重试。

所有角色均有通用 `ask_user` 工具，适用于范围、公司歧义及关键条件确认。卡片支持点击选项或补充文字；同一待答问题重复提交不会再次执行。问题与续接上下文按登录账号和工作区隔离，保存在数据库同级的 `command_questions` 目录，文件权限为 0600，24 小时后不可继续；不保存 Cookie、密钥，也不将其作为下载文件公开。

等待选择会结束当前请求，不占用一个长期等待的模型线程。`/command/chat` 和 `/command/chat/stream` 接受可选 `clarification_answer`（`question_id`、`option_id`、`text`）；待答状态为 `waiting_input`，字段为 `clarification`，并行问题另有 `clarifications`。`GET /command/clarifications/{id}?workspace_id=...` 只核验状态，不触发执行。续接同一确认不重复计一次聊天额度。

## 会议连接不是持久任务

当前 `/command/chat` 是同步请求，`/command/chat/stream` 是流式连接，尚无独立持久化的完整 command 任务列表及恢复接口。上述待答问题可以核验并续接，但普通执行过程刷新、关闭网页或连接断开后，不承诺恢复整场会议的最终回复。

- 页面将遗留“运行中”会议标为“结果待确认”，不会重新 POST 或重发 AI 请求。
- 已由工具提交的取数、转写等真实后台任务可以继续运行，应在相应任务页核对后再重试，避免重复付费或打包。
- 暂停只影响当前账号的相应会议，不等于取消已经提交给其他服务的后台任务；暂停过久会结束该连接的等待。
- 额度不足返回 429；请求失败、无有效结果和连接中断不冒充成功。

要实现完整离页恢复，仍需独立的、按账号持久保存的会议任务协议；不能用浏览器 localStorage 的“running”标签替代后端任务状态。

## 账号与文件边界

确认 `/user-auth/status` 身份后才读取该账号的浏览器会话及下载记录。切换身份会清理可见草稿、旧任务轮询与旧回答回调；不自动导入无法证明归属的旧版浏览器记录，也不删除这些记录。

生成的文件写入下载根目录下服务器派生的用户目录与工作区摘要目录。客户端提交的是逻辑工作区编号，不是目录路径。流式、并行和打包线程继承请求身份，退出后恢复上下文。

文件响应使用 `private, no-store` 及 `CDN-Cache-Control: no-store`，不再额外创建管理员会话下载同一个私人文件以“预热”公网。底层已下载 PDF 的缓存不因此删除。

升级前的无归属文件保持原样，不删除、不搬移、不覆盖。普通账号不能因为知道旧工作区编号就取得文件；管理员可核对旧目录中的资料，再单独确认后续归属。账号重新注册或浏览器记录迁移不构成归属证据。

## 数据准确性

- 本地 SQL 使用配置路径、`mode=ro` 与 `PRAGMA query_only=ON`，读取失败不会创建空数据库。
- 新闻、概念与研报使用实际表字段；空股票代码或空关键词不会自动扩成全市场检索。时间范围参与筛选，字面百分号等不作为 SQL 通配符扩大召回。
- 财务走现有 Tushare 网关，年报走巨潮年报接口；查年报元数据不自动下载 PDF，不以券商研报代替企业年报。
- 历史行情保留日、周、月、年周期，排除无效日期及非有限报价。所有结果仍应结合来源、日期和复权口径解释。
- 缺口仅在本次返回中保留尝试过程，不将用户研究问题写入其他账号可读的共享缺口列表。

## 发布与验收

共享 SPA、独立登录与 AI 新闻构建产物使用不同资源根目录，必须分别检查 HTML 引用的真实 JS/CSS，不以页面 HTML 返回 200 当作前端成功。不存在的资源必须 404，不回退 SPA。

上线只替换明确指定的 Web 镜像，保留采集容器及七个既有数据卷；保存上一固定镜像和部署控制文件以便代码级回滚，不回退或恢复数据库。

离线合成数据、ASGI、真实线程、前端组件测试可证明协议与边界，但不能证明真实模型的分析质量、上游完整性或所有已登录业务流已验收。线上验收需另检查真实登录、页面渲染、任务提交、结果与下载；不为验收自动批量调用收费模型或下载源附件。
