# 自选股研究工作区

`/super-watchlist` 用于围绕自己关注的公司，完成“选股 → 看证据 → 研究 → 验证”。它不是自动买卖系统，也不会因为打开页面就启动 AI 分析。后台是否持续采集，取决于部署中的 worker、来源配置和访问权限。

## 按四步使用

1. **选一家公司。** 在左侧“我的自选”输入名称或代码加入，点击股票切换。先看顶部实际报价时间，再看“总览”的经营与估值、分时图，以及各渠道最新资料。新增股票即使尚无数据，也应保留在自选中；空白指标不代表公司没有业务或没有风险。
2. **核对证据。** 从“值得先看的资料”点开公告、研报或观点原文；进入“财务与资金”时对照财报期、估值日期和技术指标日期。资料少或日期旧，先判断是没有披露、尚未同步，还是上游失败，不把同步次数当作事件热度。
3. **形成研究问题。** “一致预期”把券商数字与小作文提取结果分开。需要继续研究时，点击“问 AI 这只股票”：跳到问股页并预填公司、代码、当前报价时间及核验要求，仍需用户检查并发送；不会自动发送，也不声称已经把当前页面全部原文附给模型。
4. **回到原文验证。** 逐项核对预测主体、预测期、来源和兑现条件。小作文与公开股评仍是待核验线索；可在资料库换来源交叉对照，在问股输入中补充明确的验证问题。“我的研究任务”进入任务中心；打开任务中心本身不会创建研究或回测任务。

## 四个主入口

| 主入口 | 主要内容 | 地址中的栏目 |
| --- | --- | --- |
| 总览 | 行情图、经营与估值摘要、四类近期资料 | `section=overview`，默认可省略 |
| 财务与资金 | 财务估值、资金筹码两个子栏目 | `section=fundamental` / `capital` |
| 一致预期 | 小作文专项预期、券商结构化预测、原文核验 | `section=consensus` |
| 资料库 | 研究资料、公告研报、小作文、新闻与提示、股评监控 | `section=evidence` / `institution` / `essay` / `messages` / `comments` |

股票、当前栏目、资料类型、关键词与页码保存在地址中，例如 `/super-watchlist?symbol=603306.SH&section=institution&material=announcements&query=半年报&page=2`。刷新、前进或后退会恢复当前阅读位置；输入关键词替换当前历史项，不会每打一个字就增加一次后退步骤，翻页则保留可后退的记录。进入问股或任务中心后，浏览器返回同一地址仍可恢复当前筛选与页码；不会因此自动发送 AI 请求或创建任务。

同一股票的栏目切换会在本次页面会话中记住各自的关键词、类型和页码；切回主入口时恢复上次使用的子栏目，重复点击当前栏目不清空条件。整页刷新只恢复地址中当前栏目的位置，不承诺恢复其他栏目的会话内记忆。主动换股票或已选股票被删除后回退时，清除旧股票的关键词与页码，保留类型筛选；地址中的股票须在当前自选列表内，否则页面回到列表第一只。首次读取有效深链接时保留其筛选条件。财务与资料栏目默认收起行情图，可按需展开；一致预期使用独立研究布局。

股票工作区及相关事件读取按已保存的完整证券代码匹配，不把短代码（例如美股 `S`）匹配成所有含 `.SH / .SZ` 的 A 股；同一资料允许关联多个完整证券代码。显式证券筛选中的 `%`、`_` 等按字符处理，不是通配符；自由文字 `query` 仍保留关键词搜索语义。代码规范化由各入口负责，不将不同交易所或港美股别名擅自合并。

自选列表里的公司名称优先使用已经取得的工作区名称、行情名称，再使用已加载的股票索引名称；仅有本股票完整或短代码的名称占位不阻止索引补全。索引只按完整证券代码匹配，不拿不同交易所的同号股票补名。尚未打开的股票也能显示已有索引名称，无须预取它的工作区；确实没有名称时保留代码，不猜公司。

总览把经营摘要放在行情图之前，四张卡直接展示营业收入、归母净利润、经营现金流净额和 PE(TTM)，不只显示增长百分比。收入、利润旁保留各自来源口径的同比，指标期与金额报告期分开。桌面四列、手机两列；点击“查看财务与资金”继续核对详细指标。总览和详情使用相同金额单位（元、万元、亿元），PE 标注倍数；零值保留，未知值显示“—”，不按正负自动生成买卖判断。此摘要只使用本次工作区已有字段，不增加 API 请求或 AI 调用。

总览行情图默认使用紧凑尺寸，点击“放大行情图”恢复大图，“还原紧凑图”缩回；只是改变同一个图表的尺寸，不重建组件、不重置周期/区间、不额外读取行情。分时、日/周/月/年线和成交量保持可用；财务与资料子栏目原有的展开/收起行情行为不变。

“值得先看的资料”以公司公告、券商研究、机构段子、相关新闻四条频道预览排列，不再使用等高大卡片。桌面频道名在左、最多两条资料并列，手机按自然高度连续阅读；单条资料占整行，空频道仅保留“当前预览未载入”与对应更多入口，不推断全库没有资料。近183天、每类最多两条的读取范围直接标注，仍优先本公司研报，并保留资料关联、日期、来源、待核验标记及页内原文。此布局不减少已有预览条数，不预取详情或启动分析；各频道“更多”仍进入当前股票正确的筛选范围。

财务详情按“收入与利润 → 经营现金流 → 盈利与偿债指标 → 市场估值”分组，各区块就近显示自己使用的报表期与来源入口。两张报表期间不同或缺失时不直接作现金回收比较。净利率、毛利率、ROE、资产负债率是比率本身，正值不加涨跌正号，负值和零值保留；总览的同比仍保留变化方向。流动比率及 PE/PB/PS 以倍数展示。

财务指标、利润表、资产负债表、现金流与业绩预告分别选择有效报告期，不依赖接口返回顺序。先选最新报告期，同期依次比较报表口径、明确的最新更新标记与有效公告日期；实际公告日 `f_ann_date` 有效时优先使用，缺失或无效才回退 `ann_date`，不把二者最大值推定为修订日。合法日期须通过日历校验，错误日期不能把记录排到最前，零值也不以其他版本的非零数字补齐。利润表和现金流的单季度或母公司口径不混入公司合并金额；资产负债表同样核对合并主体，但它是期末时点，不称累计流量。`report_type=1/4` 在同期优先于 `5` 调整前原数据，但不再仅凭类型 `4` 强行压过 `1`；缺乏其他修订依据且内容不同的记录保留冲突。显式未知类型不猜测；缺少类型的旧记录可兼容读取，但不宣称已经核实合并或累计口径。[Tushare 利润表定义](https://tushare.pro/document/2?doc_id=33)、[现金流定义](https://tushare.pro/document/2?doc_id=44)

现金流文档明确 `update_flag=1` 表示最新，利润表文档仅称更新标识；本工作区采用“明确最新标记优先于公告日期”的统一读取策略，不宣称供应商为所有接口提供了完整修订全序。明确标记仅接受整数 `1` 或去除外围空白后的字符串 `"1"`，布尔值、`yes` 等不自动解释成供应商最新标记；两端日期统一只接受合法的 ASCII 数字日历日期。多个保留版本仍需按实际报告期和来源证据核对，冲突不由到达时间消除。

工作区逐表选择当前状态，不使用预告中的未来期、入库时间或外部记录编号推断“最新财报”。例如较新的指标快照只有一季度利润表，已保存的半年报利润表仍可独立选中；现金流也可以来自另一条真实记录。旧季度较晚更正仍保留在原始时间线上，但不覆盖已取得的更晚报告期。总览、详情和给 AI 的事实底稿使用相同逐表选择及来源映射。

新财务快照按来源、股票与五张源表的规范化内容生成版本身份，数据库原子插入；相同内容重复同步不产生新版本，也不修改已有事件的原文、时间或 ID。不同内容另存版本，因此迟到的旧响应不能抹掉新修订，本次缺表也不能删除此前可用的表。已有旧记录不迁移、不删除；此机制不能恢复上线前已经被覆盖且未保留的历史，也不意味着已经下载全部历史财报。

该选择查询使用 SQLite JSON `->` 运算符；部署运行库须为 SQLite 3.38 或更高版本且启用 JSON 功能，不以 Python 版本或镜像名称代替实际检查。此改动没有修改表结构，也不自动迁移、清理旧版本；上线前应在目标容器检查 `sqlite3.sqlite_version` 和 JSON 查询能力。回滚代码前需保留新版本记录，不把多个版本合并覆盖成一条旧 ID。

`fundamentals.sources.indicator / income / cashflow` 分别给出 `event_id / source / period / announced_at / report_type / selection_status`。只有已选财务区块全部来自同一真实事件、且无冲突时，兼容字段 `fundamentals.source_event_id` 才提供单一 ID；跨事件时为 `null`，不会让一个原文链接代表拼接后的所有表。新来源映射存在但某张表缺失时，该区块不回退通用来源 ID；旧响应完全没有映射时仍兼容旧单源入口。`valuation.source_event_id` 继续单独指向估值快照。

同一表在最高报告期、口径、公告及更新层级相同，却存在不同源内容时，选择状态为 `conflict`：该表金额和指标不显示为确定事实，不生成相应增长提示；保留报告期、不同内容数量及最多五个真实候选原文入口。不会用字段更齐全、内容排序、先入库或后入库代替官方修订依据。采集端也保留单次 API 响应中的等优先级候选，不以多表笛卡尔组合放大存储。缺失值不会逐字段从旧表填入新的源行，源表中的零和 `null` 各自保留。

核对入口只在 ID 为有效正整数时出现，点击才读取已入库字段，不预取原文或调用 AI；切换股票、栏目或刷新取得不同来源/冲突候选时关闭旧窗口，普通关闭后焦点回到入口。财务核对先呈现用户点击的利润表、现金流量表或财务指标，并标出“当前核对”；同条快照的其他已保存字段默认折叠、可以展开，不删除原记录。目标表没有可展示字段时局部说明缺失，不用别表替代；同 ID 切换核对类别只改变呈现、不重新取数。页面读取的是来源字段记录，不是财报 PDF。不可变版本保证限定于新的财务入库路径，估值及其他快照仍可能同步修订；窗口事件时间或入库时间不自动代表修订日期。单纯行情快照刷新不重新读取或关闭财务来源窗口。

手机收入与利润、财务比率采用两列，现金流及比率末项横跨整行，消除奇数卡片留下的半格空白；财务子栏目与行情图开关合用一行。正文、日期与核对入口保留，不以缩小字号或删除数据换取紧凑布局。

资金筹码中的融资交易保留净买入、余额、买入额与偿还额。净买入仅在买入和偿还都取得有效非负金额时相减，只有偿还额可用时仍展示它，但不把净买入当作已知；无须增加渠道请求。

总览的“查看公司公告”进入 `section=institution&material=announcements`，“查看券商研报”进入 `section=institution&material=research`，不会再落到同一个未筛选的混合列表。这类明确目的入口会清除先前关键词并回到第一页，避免旧筛选遮住要看的资料；普通栏目导航则恢复先前阅读位置。资料页的“资料筛选”可选择全部资料、公司公告、券商研究，以及下文四类研报关联；条件写入 `material`，用下拉框更改条件时回到第一页，前进、后退可恢复筛选条件。`material`、`query` 和 `page` 只处理已经取得的工作区资料，不为每次筛选或翻页另发请求；首次进入详情仍须按需读取 `view=full`，既有后台刷新不受影响。

资料类型与“展开行情图”合用一行，不重复显示“当前查看”说明。列表上方集中展示已载入数量、分页与可展开的“读取范围”；小作文的全库检索链接始终可见，不藏在说明里。多页列表底部也提供上一页、下一页和本页条目范围，读到末尾无须滑回顶部；单页与空结果不显示重复分页。点击“清除资料筛选”同时清除关键词、材料类型并回到第一页；从顶部或底部翻页都将焦点移到结果列表，并把顶部分页栏完整滚入视野，手机换行后也不依赖固定高度。关闭页内资料后保留当前筛选、页码，并回到原条目。

### 新闻与提示：先看报道，再按需核对观点

“新闻与提示”保留原 `section=messages` 路由，默认仅显示 `news / long_news` 相关新闻。机构观点（`essay`）、企业提示（登记、风险、信用、知识产权、历史变更）与全部消息可一键切换；不根据标题或来源名称猜测消息类别。未知类型只在全部消息中标为未分类，不冒充新闻或风险。企业登记、知识产权等提示也不等于负面风险。

总览“查看相关新闻”进入当前股票的新闻范围，清除旧关键词并回到第一页，不继承上一条企业提示筛选。类型选择保存在 `message=opinions / enterprise / all`，缺省或无效值按新闻处理；直接链接、浏览器前进后退均消费该条件。普通栏目切换后返回恢复同股消息类型、关键词与页码；切换股票保留所选类型但清除旧股票的关键词与页码。关键词在同股类型切换时保留，点击切换回到第一页，“清除关键词”仅清空文字、不改变当前消息类型。

每个类型按钮显示**已载入条数**，不是后台全库总数，也不是关键词命中数；下方结果数量才是当前类型与关键词的交集。列表继续每页12条，点击记录页内阅读并保留原始来源、时间和证据等级；全部消息额外标注类型，观点不能混成已证实公司事实。类型切换、筛选与翻页不额外请求工作区或调用AI，首次进入详情和页面既有自动更新逻辑不变。

手机资料导航收为一行横向滚动，与行情图开关共用一行；切换栏目或改变窗口宽度时只滚动导航自身，确保当前栏目露出，不把正文滚回页首。新闻的四类筛选采用两列按钮，保留计数和足够的点击区域。

### 原文与问股去向

- 公告、研报、财务等条目统一在当前页打开“资料详情”，先读已保存摘要或字段，不再把用户从自选看板跳到另一页。已有合法来源 URL 时，可另行打开原始 PDF 或来源网页；没有外链不生成虚假地址，也不把摘要称为完整原文。兼容入口 `/investment-monitor/feed?event=<事件ID>` 使用同一阅读组件。
- 小作文在当前页侧边窗口读取本地原文，展示可用的正文、图片与附件；外部 topic 地址只是可选入口。公开股评显示“已入库股评摘录”，仍标记待核验，不保证已经取得原帖全文；回复数缺失不伪装为零。
- 市场首页的“证据原文”带 `?symbol=<当前股票>` 进入流水，机构、催化、风险摘要可通过 `?event=<事件ID>` 定位；“查看全部新闻”使用 `?channel=news`。流水会消费这些条件，切换条件后立即重读本地结果。
- “问 AI 这只股票”使用 `/chat?prompt=...` 预填问题。它不是新研究任务的提交按钮；真正发送问股、或在一致预期点击“分析现有 N 篇 / 更新报告 · N 篇”，才进入相应分析流程，可能产生模型费用。

### 页内资料如何核对

阅读窗口保留来源和实际日期，正文使用 14px 字号；财务、资金、技术、股权、公司资料等按已有字段分组，不直接堆放整块原始 JSON。财务指标、利润表、现金流量表各自显示报告期，缺失时注明“未注明”；有记录时分开展示原披露日、实际公告日、报表类型源代码及更新标记源值，不将两个日期合并或把未知标记宣称为最新。其他表或顶层的元数据不补入当前表。金额或数量尚未统一单位时保留来源数值和说明，不能直接拿不同来源的原值作大小比较。研报作者与“调研参与方”分开，后者可能是机构或人员，不冒充作者。

程序生成的快照摘要不是原文；已知财务/资金/股权/技术快照与业绩快报优先呈现来源字段，兼容尚无内容性质标记的旧记录。列表精简记录未带具体字段、或详情请求失败时，也不会回退展示已知口径错误的旧生成摘要。新生成摘要将 `net_mf_amount` 称为资金净流入、`diluted_roe` 称为摊薄 ROE、`n_income` 称为净利润；此次不重写历史数据库。

较长的股东、机构席位、筹码等表格默认折叠，每页 20 条；研报预测明细每页 40 条。翻页只切换本条详情已取得的有效字段行，不再请求 API、不丢掉尾部记录。“已保存 N 条”不是上游全量或全历史总数；未知字段及没有可展示字段的空行不算在此数中。手机上只有表格区域横向滚动，不让整个窗口被宽表撑开。

只有字段、没有正文的非研报/公告记录直接显示“来源字段记录”，不连续堆放“无正文、无链接”提示；确有已保存说明的资料仍保留摘录。阅读窗口打开后焦点进入窗口，Tab 不跳回被遮挡页面，Esc 只关闭当前最上层窗口；关闭后返回原触发按钮。翻到首末页后焦点留在表格区域，避免当前按钮变为禁用导致键盘操作中断。共享 Drawer 与 ConfirmDialog 采用同一焦点栈，确认处理中不通过 Esc 误关底层阅读窗口；这不等于已改造所有历史自定义弹层。

每次打开资料只发起一次逻辑读取（包括 React StrictMode），失败可在窗口内重试；HTTP 客户端已有的临时错误重试仍可能产生多个网络尝试。关闭或切换条目后的迟到结果不覆盖新资料，响应事件 ID 也要匹配。401/403 会隐藏当前资料及其链接，而不是继续显示列表中的私有摘录；再次读取成功才恢复内容。普通网络失败保留已取得的安全内容，不清空整个股票页面。小作文图片加载失败有局部提示，合法附件即使暂时没有 URL 也会保留名称，不渲染危险协议或凭证型 URL。

`GET /api/v1/investment-monitor/events/{id}` 读取已保存资料，不在阅读时初始化/更新来源配置，也不加载页面不用的完整 `raw_payload`。它不是联网下载 PDF 的接口；是否有原文、附件和转写取决于对应资料实际入库状态。此只读保证仅针对该详情接口，不代表页面所有行情或显式分析操作都离线。

## 行情与财务的时间口径

行情读取共享的 `market_ticks`、`market_intraday`、`stock_daily`；经营、估值与资料读取 `monitoring_events`。页面显示的是实际取得的记录，不承诺所有字段都处于同一时点。

- **报价时间不是页面打开时间。** 股票栏和顶部共用报价展示口径，区分“收盘行情”“行情快照”和“历史行情快照”，不因页面重新读取便冠以“最新”。实际日期与时分固定按 `Asia/Shanghai` 展示，浏览器身在其他时区也不改变交易时标；日期本身没有时分时只显示日期。本地日线在排序比较时按其交易日上海时间 15:00 解释，不能把昨日收盘包装成今日实时价。
- **缺失或无时间的报价保持中性。** 没有有效正价格或标记 `quote_kind=unavailable` 时显示“行情尚未取得”，价格、涨跌幅为“—”；有价格但时间缺失或无效时保留价格、标为“报价时间未标注”，隐藏无法确认日期的涨跌幅。不用默认红色、绿色、`0%` 或“最新”掩盖未知；只有有效价格、可解析时间与有效涨跌幅同时存在时才按涨跌着色。
- **较新的报价不等于所有字段都更新。** 共享行情覆盖只接受当前股票且时间有效的记录；较旧快照不覆盖较新的报价。同日按实际时点比较，已取得的正式收盘不被当日较早盘中值覆盖。跨交易日的快照缺少开高低、成交额时，不借用前一日字段补齐。
- **估值有独立日期。** `valuation.as_of` 来自实际 `daily_basic` 记录保留的日期；旧快照未保存该日期时显示“未标注”，不借报价交易日推定估值日期。PE(TTM)、PB、PS(TTM) 是各自来源时点的历史口径，不是盈利预测。
- **报表期间分别展示。** `fundamentals.indicator_period` 只来自 `fina_indicator.end_date`，缺失时不使用利润表期；营业收入和归母净利润来自 `income`，经营现金流净额来自 `cashflow`，使用各自的 `income_period / cashflow_period`。总览卡片、财务详情和来源说明遵守这一约定，不应直接拼成同一季度结论。旧 `period` 字段保留 API 兼容，但看板不再拿它解释指标日期；旧响应没有独立字段时显示未标注。
- **同比名称保留字段含义。** `q_sales_yoy` 是单季收入同比，`or_yoy` 是累计收入同比，`tr_yoy` 是累计总收入同比；`netprofit_yoy` 与 `q_netprofit_yoy` 分别标为累计与单季归母利润同比。未取得字段显示“—”，不是零。
- **财务与其他快照的“最新”分开。** 财务按上文逐表报告期与修订依据选择；其他快照仍按各类型事件时间独立取最新，避免高频行情挤掉低频资料。筹码成本是来源模型估算，不是用户持仓；技术指标只描述过去价格状态。

### 资金筹码：先看交易，再看成本，技术解释按需展开

资金筹码页先并列展示“个股资金流”和“融资交易”，手机上改为上下阅读。资金流用以零为中心的四档横条显示小单、中单、大单与特大单买卖净额，具体数值同时保留，不只靠红绿辨认。它使用本次工作区已保存数据，不增加接口或 AI 请求，也不拿单日快照拼造连续资金趋势。

- 个股资金流使用 Tushare `moneyflow`：`net_mf_amount` 与各档 `buy_*_amount / sell_*_amount` 的源单位是万元。页面换算后标注元、万元或亿元；各档显示本档买入减卖出，**不能把各档差额相加替代接口的主动资金净流入**，订单大小也不能识别真实机构。[官方字段说明](https://tushare.pro/document/2?doc_id=170)
- 融资使用 `margin_detail`：`rzye / rzmre / rzche` 的源单位是元。融资净买入为融资买入减偿还，任一项缺失不计算；融资余额是存量，不能称作今日流入，也不与资金流净额直接相加。[官方字段说明](https://tushare.pro/document/2?doc_id=59)
- 有效零值保留；非数值、布尔值、非有限数不当作金额；负的买入、卖出、偿还或余额不用于计算。估算获利比例只接受 0～100 的百分数，不乘以 100，不带涨跌正号。

随后展示“筹码分布”；“价格状态与技术指标”“最近披露北向持股”和指标解释默认折叠，展开只读取已有字段。`capital.chip_trade_date` 与 `technical.trade_date` 分开显示。例如 8 月 28 日的筹码估算和 9 月 11 日的 RSI 即使来自同次页面响应，也不属于同日数据；筹码日期缺失时显示“未标注”，不拿行情、资金流或技术日期补齐。北向持股只标最近已保存的披露日期，不冒充当日净买入或当前实际持仓。

API 的 `cost_50pct / cost_85pct` 经统一转换后为 `cost50Pct / cost85Pct`；看板、类型与页内来源记录遵守同一命名，不因字段大小写不一致把已取得数值显示为空。成本分位与加权成本均为来源估算，不是用户真实持仓成本。

完整工作区和轻量总览均保留 `capital.chip_trade_date / moneyflow_trade_date / margin_trade_date / northbound_trade_date`，只来自各自保存的 `trade_date`；`source` 是承载这些字段的资金快照来源名称，不表示已经核验供应商模型。`overview.data_as_of.capital` 仅表示筹码日期，不再回退成资金流日期。给 AI 的事实底稿同样携带各自日期与未知边界；这是补齐输入契约，不保证模型一定正确推理，也不触发重算、历史补采或付费分析。估算获利比例、成本和净流量的有效零值仍保留，不当作缺失。

`cyq_perf.winner_rate` 是筹码模型估算的获利比例，**不是未来推荐胜率**。新资金筹码快照不再用 `>=0.7` 等阈值生成看多/看空标签；已保存旧记录在详情、列表、工作区及 SQL 情绪汇总中按中性读取。原数据库记录、原文与原指标不被改写，新闻和研究观点的情绪也不受这个专属规则影响；中性表示“不从该快照推断方向”，不是认定公司没有风险。[筹码数据说明](https://tushare.pro/document/2?doc_id=293)

### 行情图切换与比较基准

图表将资产类型、股票、周期和区间共同作为当前数据身份。切换股票、日周月年周期或显示区间后，旧身份的曲线与数值立即退出当前显示，新数据未返回前显示加载状态；不会把上只股票或上个周期的曲线换一个标题继续展示。返回数据还会核对标的、周期和区间，迟到旧响应不得覆盖新选择。只有同一身份的后台刷新可以保留上次成功曲线。

图表展示实际最后数据点时间、来源和点数，轮询刷新并不等于秒级实时；没有时间时显示“暂无时间”。单日分时按该交易日昨收比较，五日分时使用“区间基准”；日线的“昨收”取前一个日线数据点，周、月、年线则显示“上期收盘”，取前一根同周期 K 线收盘价，不能称为昨日收盘。没有足够数据点时不补造比较基准。

## 总览预览不等于全库清单

页面默认请求当前股票最近 183 天的 `view=overview`，进入其他主入口或子栏目后才请求 `view=full`，不会先为全部自选股组装重型研究上下文。

| 数据口径 | `overview` | `full` |
| --- | --- | --- |
| 公告、研究、小作文、相关新闻 | 每类最多读取 3 条；研究先取本公司资料，不足再补相关资料；卡片先显示 2 条 | 返回限量近期资料，见下文 |
| 快照 | 财务逐表选择、其余类型独立取最新记录 | 同一财务选择规则，补充股权等类型、来源状态与详细上下文 |
| 计数 | 不执行完整统计，`counts_complete=false` | 对所选股票和时间范围执行 SQL 聚合，`counts_complete=true` |
| 较重研究内容 | 不读取一致预期详情、不附全量日线或 `agent_context` | 读取已保存的一致预期与日线，组装上下文；不是执行 AI |

API 的计数标记位于 `stock.evidence.counts_complete`，总览另有 `stock.overview.evidence_counts_complete=false`。预览中的零不能解释为“全库没有这类资料”。`full` 的“完整统计”也仅指请求时间范围内已入库记录，并非覆盖所有年份、所有供应商；`raw_event_count` 是原始记录数，`event_count` 对同来源、同类型的状态快照作决策层去重，两者不应混用。

`full` 返回列表仍有边界：公告最多 20 条，研究资料取最近 200 条，另补该时间窗口内最近 3 条本公司研究，再按事件 ID 去重，故最多 203 条。后端不再将这批研究压成 20 条，以免总览可见的本公司研报切入资料库后消失。小作文专栏最多 30 条，公开股评 20 条，事实时间线 40 条。消息按新闻20条、机构观点10条、企业提示10条独立取最近记录，不借空余名额，合并去重后总量不超过40条，按事件时间、ID倒序；同一时间窗口的总览3条新闻不会再被较新观点挤出详情。overview查询数不变，full复用已载入小作文并净增一次有界查询；全量时间范围计数仍由SQL独立聚合。这仍不是全库清单，也不保证所有本公司历史资料都已载入。

总览的本公司优先在数据库限量前筛选，不是从最新三篇宽泛关联资料中再碰运气找本公司；前端在这份有限预览内再次将本公司研究排前。详情资料仍按原始时间排序，可用“本公司研究”筛选缩小范围。资料库的默认研究资料汇总排除 `stock_forum_post`，公开股评仍在“股评监控”独立保留，并未从数据库删除。

默认“研究资料”筛选不再让每日开盘、收盘、财务、资金、技术等重复状态快照挤占每页12条的研究材料。识别依据是来源的 `_evidence.contentNature=derived_summary`，并兼容已知旧类型：`realtime_quote`、`market_open_snapshot`、`market_snapshot`、`fundamental_snapshot`、`capital_chip_snapshot`、`ownership_snapshot`、`technical_factor`、`stock_comment_snapshot`。不按标题包含“快照”猜测，也不把未知类型或公司实际事件一律隐藏。已载入快照仍可在原有资料筛选里选择“数据快照”（`material=snapshots`）核对原始记录；没有快照且未选该条件时不增加此选项。默认标签改为“研究资料”，不把排除快照后的列表称为“全部资料”。过滤在前端已载入集合中执行，不额外请求、重新分析、改动数据库或后端时间线；因此仍不代表完整历史库。原始事件总数可能包含快照和股评，不等于当前筛选的可见条数。

资料库将已载入条目去重并按原始时间排序，每页 12 条；“筛选已载入资料”只筛选这些条目的标题、摘录或来源，不向全库发起搜索。因此总计数可以大于可见条数，“全部证据”的兼容栏目键不等于全部原文都已下载。

### 研报关联：召回，不等于研究这家公司

PDF 研报、券商结构化预测、机构调研和券商推荐按 `stock_relation` 显示四类关联。原始 `symbols` 索引只能说明资料曾被召回，摘要或标题提到公司也不证明该公司就是研报主体；此分类不需要下载 PDF 或调用 AI。

| 关联类别 | 如何理解与核对 |
| --- | --- |
| 本公司研究 `company_direct` | 原始研究对象代码与当前股票一致且没有主体冲突，或有明确的 `report_rc` 标的数据源契约；不是仅凭标题命中 |
| 行业研究 `industry_related` | 原始报告类型或行业字段支持行业资料身份，不等于针对当前公司作出的盈利预测 |
| 其他公司资料 `other_company_mention` | 原始主体明确为另一只股票，并列出可用主体名称、代码；只有原始标题或摘要中确有当前标的匹配摘录时，条目才具体标为“其他公司提及” |
| 关联待确认 `unknown` | 旧接口未返回关联、目标股票不一致、原始主体不明确或冲突等；筛选项称“待确认研报”，不会降级猜成“本公司研究” |

可用的标题、摘要或行业匹配依据默认折叠，展开后查看保留的短摘录；它仅解释为何关联，不证明正文已全文核验或观点属实。原始主体代码、数据源契约也可用于归属判断，但不会为没有标题／摘要命中的其他公司资料编造“提及”证据。前端拒绝错股票的关联标签与主体信息，缺失的新字段以待确认兼容；来源、原始时间和待核验状态在手机上仍保留。

资料行、原文抽屉与预期引用均保留年份，有时间的记录固定显示上海时区，不随浏览器时区变化。研究资料旧版无偏移时间按服务端 UTC 存储约定解释，再转上海时间；这与行情无偏移时间的交易所时区约定不同。公告若带 `time_precision=date`，优先只显示来源的 `disclosure_date`；不把入库规范化的午夜包装成真实披露时刻，旧记录缺失精度元数据时也不凭空补出它。

返回的是精简关联字段及必要证据标记，不把完整 `raw_payload` 放进每行页面数据；分类不会改写或删除原记录。数字能否进入一致预期还需下一节的样本资格检查，不能因为在资料库看见某篇研报，就认为它已参与当前公司的预测计算。

小作文栏目另有“用‘公司名称’检索全库”，页面底部也可进入该公司的“机构段子与录音”。链接使用 `/essay-radar/feed?query=<公司名称>`，名称缺失时使用股票代码；目的页会读取 `query` 并按关键词查询。这是名称/文本检索，不是证券 ID 精确关联，需留意简称、同名和非主体提及；“全库”指该检索模块的已入库资料，不是所有渠道的所有原文。事实流水仍可按股票、来源、频道和关键词查询；“数据一站式获取”需在目的页设置所需股票与条件。任何入口都不能保证尚未同步或未授权资料的完整覆盖。

## 一致预期：先看样本，再看数字

该栏目将“小作文 AI 专项报告”与“券商预测样本”分开。前者归纳原文中的主张，后者汇总本地 `report_rc` 结构化记录；二者都不是已披露业绩，也不代表全市场、所有机构的一致意见。标题旁状态明确标为“小作文：尚未分析 / 等待分析 / 分析完成”等，只描述小作文任务，不表示券商预测也在等待 AI。

打开栏目只读取已有结果。首次按钮为“分析现有 N 篇”，失败且尚无报告时为“重试分析 · N 篇”，已有报告时为“更新报告 · N 篇”；`N` 使用后台当前 `source_count`，不是默认凑满 25 篇，也不是历史报告的已分析篇数。0 候选时按钮禁用，不提交空任务；运行中也不重复提交。即使历史引用有很多篇，也不拿它们替代当前候选数。

尚无报告时只保留可操作状态、真实券商预测和可用候选原文，不铺空的综合结论、利润／估值卡片、证据表或时间线。当前响应完全没有券商预测材料时用简洁说明替代空表，不声称全库没有研报。已有报告即使本次无候选或更新失败，仍保留结论、可追溯预期和历史引用，并显示失败原因；旧接口仅有经营／估值文字、没有数值预期时也不丢弃。报告没有明确数值与根本没有报告是不同状态。

### 当前候选，不等于已有报告的引用

顶部“本次可分析 · 相关 / 单股”展示当前可选的最多 20 篇相关与 5 篇单股专属材料，按 topic 去重；它们可能比下方报告更新。新后端把实际分析时读到的来源元数据、材料截止和报告完成时间保存到结果中，不用本次候选清单重新解释旧报告。

| 信息 | 含义与读取字段 |
| --- | --- |
| 本次可分析材料 | `source_count`、`related_source_count`、`dedicated_source_count` 及 `candidate_source_notes`；`candidate_cutoff_at` 是候选材料的最新时间，不是报告截止 |
| 报告引用原文 | `source_notes` 是生成当前报告实际读取的来源；`report_source_count` 是可确认的输入篇数，不能用候选数量代替 |
| 报告材料截至 | `analysis_cutoff_at` 对应报告来源的实际原文日期，不是页面刷新或重新排队时间；来源日期不完整时不推定截止 |
| 报告生成 | `completed_at` 是当前可见报告的完成时间；`updated_at` 是任务记录的更新时间，不能当作新报告已经生成 |
| 报告与任务状态 | `has_report` 表示是否已有结果；`status` 反映当前分析或更新状态。等待、处理中、失败或有新材料时，仍可能保留上次报告 |

有新材料、重试或重新排队时，旧报告可以继续阅读，但页面会说明它尚未覆盖本次全部候选。不能把 `analyzed_count=0` 单独解释为“从未生成报告”，也不能把 `pending_count` 当成实际新发现的篇数或队列长度。

历史结果的来源即使已经退出最新 20+5 窗口，仍尽量按保存的 topic ID 查回原文元数据；这不是重新调用 AI。若旧数据在之前的重新排队中已经丢失完整输入清单，只展示可追溯的引用，并用 `report_sources_complete=false` 标记不完整；未知的篇数、材料截止与完成时间不补造。新结果保存的是来源元数据，不为此额外复制全文或改写原文日期。

旧接口没有 `has_report` 等来源契约时，前端把其来源列表标为“当前候选原文”，不冒称历史报告的实际引用；旧 `analysis_cutoff_at` 不作为可信的报告材料截止。报告生成时间按可用的 `completed_at` 显示，缺失则保留未知。

### 如何核对一条小作文预期

“关键预期证据”按观点提出时间排列，可按收入、利润、EPS、目标价、市值等实际已有指标筛选，每页 6 条。筛选与翻页只整理已保存报告，不触发新的分析；“预测时间线”默认折叠，仅展示按时间排序的前 8 条预期，完整条目仍在分页表中。

每行分开显示提出时间、预测期、指标、原文数值、主体口径和相关/单股样本类型。提出时间优先使用有效的 `proposed_at`，否则使用原文 `event_at`；不能把“何时说”与“预测何时”混为一谈。原文单位明确时随条目显示，未注明时写“单位未注明，不换算”；不同预测期、上市公司与子公司等不同主体不合并成一个数字。点击行或引用卡片可在页内核对原文；“检索原文”另以公司名称进入全库关键词检索，不保证精确证券关联。

### 从看板发起公司研究

看板的“问 AI 这只股票”把当前 `stock/name` 与预填问题一同传入问股；问股优先建立这个明确标的上下文，不把“比较事实与预期”误解为继续沿用旧公司。预填不自动发送、不读取旧报告，旧会话恢复或报告异步返回不能覆盖新标的。用户真正输入多股比较时仍维持现有比较行为，主动改问另一股票时可正常切换。

### 券商数量：覆盖、筛除与有效样本

完整工作区独立读取当前股票、请求时间窗口内最近最多 200 条 `institution_forecast` 记录，不再让 PDF 研报或调研记录挤占这批预测样本。总览不读取这批详情；`broker_sample.loaded=false` 表示尚未加载，不能解释为零覆盖。

| 口径 | 字段与使用限制 |
| --- | --- |
| 已收录原始记录 | `broker_report_count` 保留兼容含义；`broker_sample.total_record_count` 同样是当前股票与窗口的原始记录数，可能包含旧新重复，既不是文档数，也不是机构数 |
| 读取与资格检查 | `loaded_record_count` 是本次实际读取的原始条数；`relation_excluded_count` 是明确他股或主体冲突的排除条数，`input_record_count` 是排除后进入去重的记录数，满足 `loaded = input + excluded` |
| 本次去重文档 | `report_count` 是合格输入按自然键去重后的文档数，`duplicate_record_count` 是 `input_record_count` 与它的差；`truncated=true` 表示本次只读取了部分原始记录、未覆盖窗口全部记录 |
| 含有效数字的文档 | `valid_report_count` 指至少贡献一个有效目标价或分期预测指标的文档，并不保证每份都有 EPS、利润等所有指标 |
| 每个指标的有效样本 | 每个预测期的 `report_count` 是有贡献的文档数；`metric_sample_counts` 分别计 EPS、净利润、PE、营业收入、ROE 的有效文档数。旧 `sample_count` 是该期单个指标样本数的最大值，不是机构数 |

页面显示本次读取、去重、有效样本以及材料日期范围，数值单元格分别标注有效样本数；接口未提供新契约时，明确显示旧计数边界。`broker_sample.oldest_at/as_of` 是这批券商材料的日期范围，不是来源最近同步时间，也不能使用混合了其他来源的旧 `consensus.as_of` 代替。

明确为其他公司或 `has_subject_conflict=true` 的原始记录先排除，不进入评级、目标价、分期数字或计算来源清单。仍无法确认本公司归属、但没有明确他股冲突的旧记录暂保留：`unknown_relation_count` 统计去重后所有非 `company_direct` 文档，页面明确提示使用前核对来源；它不等于这些记录已经核验属于本公司，也不只包含 `kind=unknown`。资格判断、文档去重和引用清单共用同一份当前股票关联，不借其他股票缓存的标签放行数字。

计算按文档等权、按预测期分别进行。同一文档、同一期、同一指标重复且值相同只计一次；若有多个不同值，则剔除该文档的这个冲突指标，其他明确指标仍可使用，接口在 `conflicting_metric_counts` 记录剔除数。预测期缺失的记录不混入分期中位数，并在 `missing_period_report_count` 记录涉及的文档数；同一文档的明确期间记录仍可参与。非数值、布尔值、非有限数不参与计算；财务预测中的有效零值或负值不是缺失。

券商表的净利润将 `report_rc` 原始万元除以 10,000 显示为亿元，EPS 以元、PE 以倍展示。ROE 显示“源值”，不擅自推定百分比或比例缩放；官方字段说明没有标明该字段缩放。后端原始数值单位不因此改变。这套规则不自动统一不同会计口径、公司主体或机构的期间写法，不能跨期直接比较中位数。[report_rc 官方字段说明](https://tushare.pro/document/2?doc_id=292)

### 目标价、来源与历史缺口

新主指标为“文档目标价中位”：每份文档有有效目标价上下限时先取区间中点，只有单边目标价时用该值，再对文档等权求中位数；相同上下限只产生一个文档值，非正目标价不参与。它不是机构等权，也不是所有机构各取最新一次修订的共识。

本次没有有效目标价时不铺三张空卡，保留可用的分期盈利预测与来源；不能把目标价缺失理解为没有券商资料。

`target_price.document_count/document_median` 表示上述文档口径；`document_min/document_max` 是文档中点的最小和最大值。页面两侧“原文目标价下限 / 上限”仍使用原始区间的 `min/max`，不与文档中点范围混淆。兼容字段 `median` 和 `sample_count` 保留旧端点中位及端点计数，另有 `endpoint_count` 明确该计数；旧接口只能标为“目标价端点中位”，不能改名冒充文档或机构中位。

算法示例（非真实报价）：三份报告区间分别为 100～200、110～120、130～140，中点为 150、115、135，文档中位为 135；六个端点的旧中位则是 125。同一原文的区间端点不能被当作两份独立研报。

“查看计算来源”默认折叠，每页 12 份，按事件 ID 在看板内打开来源记录；关闭回到原条目，不跳出当前股票。“全部来源”是本次读取的去重文档清单，不表示每份都贡献了每个指标。

EPS、净利润、PE、ROE 有有效数值和逐指标 `metric_source_event_ids` 时，数字可点击：只展示该预测期、该指标真正参与计算的来源，不能用整期 `source_event_ids` 或全部研报代替。重复 ID 去重；无效 ID 不请求，旧接口未提供逐项来源时数字保持普通文本。来源标题缺失但 ID 有效时可以读取该记录，不编造标题或机构。冲突样本数按 `conflicting_metric_counts` 明示；更换指标、股票、栏目或当前来源标识集合后，不延用上一组阅读窗和页码。选择与翻页仅处理已取得的来源索引，点击具体研报才发送详情 GET，不预取每篇、不调用 AI。

页内研报字段表保留预测期、EPS、PE、净利润（万元）、营业收入（万元）与 ROE（源值）；缺失项留空、零和负数保留。来源表以万元展示便于对照接口，汇总净利润仍用亿元，两者不是数值矛盾。窗口读取来源记录当前保存版本，同步可能修订同一 ID；不能把当前字段冒充某次计算的不可变快照。完整 PDF 是否可打开取决于实际保存链接。

机构只认明确保存的 `org_name`，不把作者当机构。页面分开显示可确认的 `known_institution_count` 和未注明机构的 `unknown_institution_report_count`；存在未知机构时，完整 `institution_count` 为未知，不虚构一个“未知机构”。机构名称也尚未做完整别名归并，不声称已覆盖多少家独立机构的全部意见。

研报接入的新外部 ID 包含股票代码；同一份覆盖多只股票的研报可分别保存各股票预测，不再相互覆盖。同股票下旧、新 ID 共存时按来源、股票及研报自然标识去重计算，不删除或迁移原始记录。历史上已经被跨股票覆盖而丢失的记录不能靠统计修复猜回；需要后续正常重采取得原始数据。因此本次修复保证后续接入幂等和计算口径，不承诺历史覆盖已完整恢复。

## 加载、缓存与主动操作

### 从进入页面到看到数据

“正在确认访问权限”对应会话检查，“正在准备当前账号页面”对应私有页面的账号隔离，“正在加载页面组件”对应 JavaScript 分包。它们不是同一项工作，也没有可测的统一完成百分比。鉴权未通过时不挂载私有内容；切换账号会卸载旧账号业务视图，同身份常规会话刷新不因此重建整个页面。

页面组件就绪后，路由边界立即展示子页面，不等待首批 API 全部结束。顶部细线仅在初始请求等待约 180 毫秒后出现，且约 1.4 秒内结束；它没有确定的百分比，消失也不表示接口已完成。仍在读取的模块继续自己的加载提示，失败由对应模块提供重试。不会用固定的“18%”或“数据完整后一次性显示”解释未知进度。

股票列表、当前股票工作区和共享行情独立读取。工作区缓存按股票与 `overview/full` 分开；旧股票的迟到结果不会作为另一只股票的数据展示。切换到详情尚未返回时，页面保留当前股票已取得的行情与总览，并显示该栏目的加载状态。首次失败提供重试，后台刷新失败保留上次成功内容；保留缓存不表示本次同步成功。

自选增删操作在页面内串行处理，以本次保存接口返回的列表为准；操作开始前发出的旧列表请求不能将新加入的股票撤销、或把已删除股票放回来。保存失败后允许新一轮列表核对，不被旧请求占用。重复加入已有股票会定位该股票，兼容列表中的六位旧代码与带交易所代码；只有唯一匹配才切换，明确的沪深不同市场代码不能相互冒充。这不保证跨设备同时修改时的服务端事务顺序。

一致预期按股票分别保存当前提交与观察状态。完整工作区取得更新的已完成结果后，可直接恢复报告和按钮，不必再次调用 AI；旧轮询不能覆盖新提交，也不能因匹配上一次已完成报告而提前结束新任务的观察。判断新旧使用任务 `updated_at`，不使用可能仍属于上次报告的 `completed_at`；缺失任务更新时间时不推定旧工作区已经完成新任务。同一任务版本的候选材料投影可以更新，不被旧轮询副本永久覆盖。网络错误或约三分钟观察窗口结束不等于后台任务已停止，返回栏目后仍可读取已保存结果。

### 预加载只准备当前入口需要的内容

- 自选导航预取自选列表，以及列表第一只股票的 `view=overview`。这不保证恰好是地址中的目标股票；真正进入页面后仍按当前选择读取。悬停导航不再请求行情历史，避免仅路过入口便触发行情补采，也不预取 `full`。
- “我的研究任务”只预加载页面代码，不在导航阶段请求五类任务；进入页面后由各任务渠道独立读取。“机构段子与录音”只预取共用状态，不为检索页提前计算研判聚合。
- 数据预加载在页面隐藏时跳过，分包与数据预加载共用省流量及 `2g` / `slow-2g` 守卫；没有浏览器网络信息时不能承诺自动识别所有弱网。同一预加载器约 15 秒内复用本轮请求，实际 API 另有自己的缓存，不代表全部页面、所有请求均已去重或可离线使用。

### 缓存与显式操作

浏览器工作区请求缓存的有效期为 30 秒，过期后等待并将本轮响应返回页面，而不是只把新结果留在未订阅的后台缓存；同条件在途请求仍合并。服务端按数据库、股票、时间范围和视图隔离缓存：总览 30 秒、完整工作区 120 秒；超过有效期但未超过 900 秒时，可先返回原快照并在后台重新组装本地数据。服务端每次读取还会尝试覆盖较新的本地共享报价，因此证据生成时间与报价时间可能不同。页面可见时约每 60 秒重读当前工作区；浏览器焦点、可见性变化也可触发合并后的刷新，不代表外部来源有新数据。

总览与完整工作区不再各自长期保留互相矛盾的新闻：显式成功刷新总览，或总览发现完整缓存未包含的新闻及其修订，会使同股票、同日期范围的完整缓存失效。比较新闻 ID、标题、来源、日期、链接、前 240 个字符和证据等级；只有报价、生成时间或条数变化时不重算完整资料。此机制不扫描全库，也不能证明未进入总览预览的其他记录没有变化。

若完整读取期间总览已被更新，服务端不会让迟到旧结果恢复缓存，并标记 `cache.state=superseded`；仍有效的浏览器请求最多重读一次本地工作区。连续更新未收敛时保留已有页面内容并提供重试，不无限循环。退出登录或被更新请求替换的旧读取不再补发重试；同内容的普通总览后台重建不应重复触发重型查询。这是浏览器及单个服务进程内的缓存协调，不是跨进程事务或外部数据实时性保证。

以下操作应明确区分：

- 工作区 GET、切栏目触发的工作区请求、`refresh=true` 和“重试当前股票”：只读或重组本地工作区，不直接请求上游，也不启动 AI。这个保证只针对工作区接口，不涵盖页面上的所有独立请求。
- 行情图另走历史行情接口；本地分时缺失、交易日不完整或完全没有行情时，即使 `refresh=false`，现有行情服务也可能向上游补采。不能因为工作区只读，就把打开整个页面称为严格离线操作。
- 顶部“刷新”：调用共享刷新 POST，刷新共享行情、重建本地小作文关键词索引并唤醒到期来源，可能访问上游；它不是单纯的页面重绘。
- 加入自选：保存个人关注关系；当前实现对首次进入共享采集池的股票安排 183 天回填并唤醒相关 worker，已在共享池中的股票复用已有采集。回填是后台任务，不保证加入时已经补齐；worker 关闭或来源不可用时仍需等待或处理失败状态。
- 一致预期“分析现有 N 篇 / 更新报告 · N 篇”：仅在当前有候选且没有进行中任务时显式排队，最多 20 篇相关及 5 篇单股专属原文，按 topic 去重；与只读取已保存结果分开。券商预测与小作文结果始终分列，不能混算为已确认业绩。

这些缓存与读取规则不改变公共市场数据的认证边界，也没有新建一套私有行情采集器。

## 在“我的研究任务”继续处理

`/tasks` 汇总行业与公司调研、量化研究、录音转写与纪要、录音文件打包、一站式取数五类任务。顶部“正在处理 / 已完成 / 需要处理 / 已读取任务”只统计当前已经返回的记录，“已完成”包含部分完成；状态数量不是全历史总量，也不会因选择了某一任务类型就变成该类型的服务端统计。

可按任务类型与状态筛选已读取记录，列表每页 20 条。“读取范围与历史任务”分别列出各类型的已读取数量与接口总数；发现历史未加载时会提示。调研支持每次“再读取 30 条历史调研”，并按任务 ID 去重；其他类型当前列表接口只返回最近记录，不支持历史翻页，入口会带用户回到对应任务模块。因此客户端“下一页”只翻已读取结果，不能视为自动取回所有历史。

页面可见时，有运行或排队任务的类型约每 10 秒更新；临时读取失败的类型约每 30 秒重试。401/403 隐藏该类私有快照并停止自动轮询；400/404/422 按接口或请求不兼容处理，停止定时重试，保留手动与重新激活后的复查入口。多渠道问题合并为一条可展开摘要，已读取成功的任务继续展示，不用整屏错误遮住结果。

空列表与已完成类型主要在进入或重新激活页面时更新，不为五类任务持续空转。量化与取数任务列表在一秒新鲜缓存过期后，调用方会等待并收到本轮真实响应，不再只得到旧的空列表、把新任务留在无人读取的后台缓存里；同一进行中请求仍合并。已加载的历史调研页也纳入刷新；列表加载失败、未读取和真实空结果分别展示。

点击任务返回其已有详情或结果：调研定位项目，完成的量化任务定位结果运行，录音任务定位转写/纪要或打包，取数定位任务记录。查看或翻页不会自动提交新的 AI、采集或回测任务。

## 从个股进入原文检索

带股票名称进入“检索原文”后，保留明确的关键词、全文/标题范围及小作文类型约束。检索请求失败会显示局部失败和重试入口，不再把 422 版本不兼容等错误描述为“正在准备索引”并无限等待。不会为适配旧接口而静默丢掉筛选参数；旧后端必须升级对应接口才能满足新筛选能力。

进行中的慢请求跨多个 15 秒页面刷新周期仍只发送一次；换关键词或筛选后，上一条件的迟到响应不覆盖新条件。已有结果可保留供对照，但会标明不是当前筛选的结果，并禁止误选或导出。401/403/400/422 暂停该检索的自动重试，临时错误保留重试能力；页面其他已读取内容不清空。

### 检索计数的去重与时效边界

后端只优化结果总数的计算，不删减原文或放宽筛选。适用的全文检索计数将正文与分析字段的命中分别查询，再用 `UNION` 去除同一篇原文的重复命中；多个关键词仍可分别命中正文和分析字段。标题检索、已有选择性 AI 条件等继续使用原计数路径。行列表的排序、分页及导出仍沿用原查询，不因计数优化省略未分析原文。

计数使用进程内、按数据库对象与规范化筛选条件隔离的 30 秒缓存，最多 256 项；时间下限的缓存键目前规范到分钟。相同键的首次并发请求共享一项在途计数，其他条件不等待这把扫描；扫描失败会传播失败并释放在途项，不把失败缓存成零。后续页可复用已算出的总数，但客户端 `known_total` 只是提示，不能改写服务端事实计数。

该缓存不是跨进程共享，也不是每次请求的事务快照：持续入库或同分钟的时间边界变化可能使计数短暂滞后，页面行数据仍独立读取。首个冷查询仍需扫描，行查询、原文读取和网络耗时也未因此消失。单次本地前后对比不能推导为稳定“7 倍提速”，更不能等同云端时延或多用户并发能力；应使用同库、同条件、明确冷热状态的独立测量判断效果。

## 市场首页的个人自选隔离

`/app` 的个人自选卡片按当前已认证用户的完整自选列表组装，不再与全局 `STOCK_LIST` 取交集。下一次成功读取首页接口时，用户新加但不在全局配置中的股票也会出现；没有本地行情或证据则保留股票和缺失状态，不用别人的自选补位。管理员或关闭用户访问控制的旧模式仍保留原有全局展示。

前端按账号、认证方式和访问模式隔离成功快照；账号切换会重建私有视图、清理共享首页请求缓存，并拒绝旧账号迟到响应。另一个独立缓存只保留允许复用的公共行情与新闻，不含自选列表、个人相关事件或警告。新账号请求等待或失败时显示读取状态，不误报“没有自选股”。旧的无账号 v2 缓存不再读取。

首页 HTTP 响应使用 `Cache-Control: no-store, private` 和 `Vary: Cookie, Authorization`；应用自身允许按账号保留最多 12 小时的成功快照，供离线或暂时失败时恢复。两者不是同一种缓存，应用缓存也不等于浏览器存储加密。账号隔离不代表行情必然新鲜，应始终看实际时间；同一账号的自选增删可能等待下一轮成功读取才反映到首页。
