# AI 新闻热点

入口 `/ai-news`，使用乐子乌现有的注册、审核、登录权限。新闻页复用站内 `Shell`、侧栏、手机导航、主题与磨砂玻璃样式，不再提供另一套品牌顶栏和独立主题。新闻不属于个人任务，不包含用户资料。

## 数据与显示

参考 [AIHOT](https://github.com/KKKKhazix/AIHOT) 的开源信源配置与热度方法（核验提交 `885b736dc0fd3ef3d4c9c70af2bc3a981a99ff38`），在现有 Python / React 架构中独立实现，不安装第二套 Node/PostgreSQL 服务。

**没有使用 AIHOT 线上 API、RSS 输出、数据库、Logo 或字体**。其线上数据公开再分发需要另行书面授权，MIT 代码许可不涵盖线上数据，参见 [官方使用规则](https://aihot.news/terms)。本功能不是 AIHOT 官方合作或完整部署。

来源包括 OpenAI、Google DeepMind、Google Research、Hugging Face、Microsoft Research、NVIDIA、AWS Machine Learning、GitHub AI、Mistral、Berkeley AI Research、TechCrunch AI、The Verge AI、The Decoder、Simon Willison，以及中文量子位、雷峰网 AI 与 IT之家公开订阅。综合科技订阅只收录标题明确涉及 AI 的内容，不把所有科技新闻混入。本页保存标题、来源、原文地址、发布时间、收录时间、规则主题及订阅提供的短简述；不另抓新闻全文或图片，不调用模型生成或翻译文章。简述去除 HTML，限制为 160 字符且英文最多 25 词，明确标注为来源简述，不伪装成 AI 研判。原文及版权属于发布者；如发布方调整订阅或授权，应停用相应源。

- **热点**：同一原文地址或标准化后完全相同的标题保守归组，保留版本数字、否定词与词序，不使用模糊相似度或 AI 语义聚类。48 小时内每个独立发布主体最多贡献一次权重，24 小时半衰期。至少两个独立主体才标记多源热点。Google 两源合并计主体；GitHub 和 Microsoft 合并计主体。
- **最新**：按来源实际发布时间排列；无日期记录明确使用收录时间，不伪装为刚发布。
- **筛选**：24 小时/7 天/30 天、来源、规则主题、标题与订阅短简述关键词；关键词需点击搜索。支持部分中文公司别名。不是全文或语义搜索。
- **来源**：每源显示最近成功、尝试、错误和当前窗口条数。单源故障保留旧条目，不能把缓存失败当作没有新闻。

## 阅读界面

页头与筛选采用共享玻璃材质，阅读卡片保持足够对比度。默认最新动态，按日期分段、每条显示时间、来源、标题与可选简述；来源与主题筛选无需跳去其他模块。自动轮询发现新内容时提示用户载入，不在阅读中强行插入条目导致页面跳动。桌面与手机复用现有主导航，跨模块链接能正常返回主站。不同主题与无数据、上游失败状态均有对应显示，不制造热度、虚假评分或摘要。

这些是所接订阅源中的相似标题和时间加权指标，不是全网热榜、阅读量、投资建议或 AI 语义事件归因。源内容多数为英文原始标题；不自动生成未经验证的中文标题。

## 更新与资源

API `GET /api/v1/ai-news/feed` 只读本地快照。过滤参数 `view=hot|latest`、`q`、`topic`、`source`、`window=24h|7d|30d`、`page`、`page_size`。响应包含条目、分页、来源状态、主题计数、更新时间和是否陈旧。

API 服务启动一个轻量 RSS 线程；若部署关闭应用 lifespan，则首次已登录新闻请求仅启动这一个 RSS 线程，不启动任何业务采集/AI 任务。最多 4 个并行请求，媒体源默认每 5 分钟、官方/研究源每 15 分钟检查，保留 ETag/Last-Modified 条件请求及有界失败退避。页面每分钟静默读缓存，后台标签不轮询，恢复可见时刷新。来源本身的发布周期和网络连通性仍会影响到达时间，这不是秒级推送服务。

响应分别提供最近检查 `last_checked_at`、新内容入库 `content_updated_at`、来源最新发布时间 `latest_published_at`，避免把“检查成功但无新增”显示成刚发布新闻。每源提供下次检查时间和间隔。旧缓存保持兼容，不重置或清空已有记录。

解析有字节、超时、跳转和公共地址限制；不执行订阅内容。支持有界 gzip/deflate 解压，压缩前后均限 4 MiB；CDATA 内的 HTML 声明不当作 XML DTD，但真正的 DTD/实体仍被拒绝。TLS 和公共地址校验不关闭，不通过代理规避不可达或被拒绝的来源。Unix 文件锁避免多进程重复采集；Windows 部署只启一个 API 进程。

`AI_NEWS_AUTO_START=true` 控制采集；关闭后只读已有缓存。`AI_NEWS_MEDIA_INTERVAL_SECONDS=300`、`AI_NEWS_OFFICIAL_INTERVAL_SECONDS=900` 控制检查周期，限制在 300–3600 秒，非法值回退默认值；失败按 5 分钟起退避、最长 30 分钟。`AI_NEWS_CACHE_PATH=data/ai-news/cache.json` 为独立可原子替换的缓存，保留 90 天、最多 5000 条元数据。不建表、不更改投资/用户数据库、不下载附件、不消耗 LLM token。

## 独立构建与部署

```sh
cd apps/dsa-web
npx vite build --config vite.ai-news.config.ts
```

输出 `dist-ai-news`；HTML 安装到 `static/ai-news/ai-news.html`，该目录下的散列 JS/CSS 安装到 `static/assets/ai-news/`（独立构建 base 为 `/assets/ai-news/`）。不要用本地脏工作区的主站 build 覆盖生产 `static`。

独立构建仅是发布隔离边界，不是另一套用户界面：它加载同一 `Shell` 和导航组件，通过原生文档导航进入其他模块，防止局部路由器误接管主站路径。独立构建关闭无关页面预加载，不在打开新闻时初始化其他采集或分析任务；主站正常构建保留原预加载能力。

对尚未整站重建的生产 SPA，可把 `apps/dsa-web/ai-news-nav.js` 按内容散列安装到 `/assets/`，仅在经过校验的原生产 `index.html` 加载它。它只向桌面主导航和手机抽屉插入原生链接，不扩容手机底栏、不请求接口、不读取身份信息；检测到主 SPA 已有原生入口时不再插入。后续正常整站构建采用 `SidebarNav` 中的正式入口，并移除过渡脚本。

后端变更为新增 endpoint/service 与 `api/app.py`、`api/v1/router.py` 窄补丁。独立登录入口严格匹配 `/access?redirect=/ai-news`，原 `/access` 和现有页面保持兼容；API 与页面不加入匿名白名单。JS/CSS 位于原有公开 `/assets/` 命名空间，没有放宽业务鉴权。

生产发布必须核对当前版本、镜像、数据卷与 `MAINTENANCE`。恢复守护配置失配时先审查并取得维护许可，不绕过哈希检查。回滚只还原本次程序文件和入口，保留缓存及所有原数据，不操作其他网站或采集容器。新功能本地完成不等于已上线，应以部署记录与线上真实访问证据为准。

Mac mini 的网站和采集服务可能使用不同的已批准镜像。恢复守护使用精确 `expected_image_ids` 映射分别校验 `server`、`monitor-worker`，并维持控制文件 SHA256、七个卷名称/挂载权限、维护标志和禁止不健康服务自动重启等约束；不得由当前运行镜像自动推导批准值。发布持有与守护相同的锁，仅重建 `server`，保留旧镜像。回滚也必须先复核身份、控制文件和挂载，最后通过健康、鉴权与守护检查才能撤除本次维护标记。

## 测试

`tests/test_ai_news.py` 覆盖 RSS/Atom、日期、恶意链接/XML、去重、热点口径、持久化、失败保留和接口鉴权。前端独立构建与浏览器验证分别记录，不能以 HTTP 200 代替页面验收。

前端回归包含新闻页、匿名/已登录回跳、原生导航桥接、手机底栏不扩容、React 重挂载去重与来源陈旧状态。上线前在无网络、无生产卷的候选镜像中检验真实后端路由/资源和原站主 bundle 散列；上线后分别验证公网、源站、实际 RSS 缓存以及 worker 的 ID/启动时间不变。
