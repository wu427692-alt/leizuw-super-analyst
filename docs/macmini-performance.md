# Mac mini 加载性能配置与验收

2026-09-15 已按用户批准的本地数据恢复到 M4 / 16 GiB Mac mini，原生 ARM64 r2 镜像的 656 个文件校验通过；Cloudflare Tunnel 已接通公网首页与登录入口。原云端最终数据未找到，本次恢复不能等同于找回所有云端用户和任务。完整状态见 [迁移手册](macmini-migration.md)。以下严格区分函数读取、首次加载和公网耗时，不以隐藏加载提示、延长旧行情寿命或关闭功能作为提速。

## 本轮处理的等待来源

| 等待来源 | 处理 | 验证边界 |
| --- | --- | --- |
| 概念页预加载 100 条，页面实际桌面 24 / 手机 10 条，缓存无法复用 | 按实际首屏参数预取；同义参数统一缓存键 | 桌面、手机的“预热＋打开”均由 2 请求变 1 请求 |
| 行业调研预加载 30 条，任务页实际 12 条 | 使用实际首屏分页参数 | “预热＋打开”由 2 请求变 1 请求 |
| 手机点导航后才请求数据 | 触摸与键盘聚焦时并行预热代码和数据 | 页面保持原功能；退出账号使旧预加载失效 |
| 首页已命中缓存，仍逐股解析 200 条事件并统计 | 按数据库与股票短缓存公共事实；相同并发请求合并 | 事实缓存 15 秒、最多 256 股票；自选成员和最新价格每次独立读取 |
| 自选首屏是总览，启动却只预热详情 | 先预热总览，再预热完整资料 | 保留原两种视图，不用空总览代替详情 |
| 小云机配置让多渠道取数串行排队 | Mac mini 独立配置读缓存、预热并发、采集并发及资源预算 | 预览隔离、原鉴权与正式切换开关保持原规则 |

不缓存账号私有列表，不把上个用户的预加载传入新会话。事件事实与行情分开：15 秒事实短缓存不会把股价固定 15 秒；真实日期和来源保持原语义。首页同股并发失败会唤醒等待请求，失败不写入成功缓存。

## 16 GB Mac mini 的初始预算

采用已准备的原生 ARM64 Colima 实例，虚拟机 4 CPU / 8 GiB。网页 API 与采集分别使用容器，数据库使用 Linux named volumes；保留一份 API 进程，避免增加 Uvicorn 进程重复启动采集和 AI 任务。

| 配置 | 网页 API | 采集进程 |
| --- | --- | --- |
| CPU 上限 | 3 核 | 1 核 |
| 内存上限 | 5 GiB | 1.5 GiB |
| SQLite 常驻连接＋临时连接 | 8＋4 | 4＋0 |
| 每连接页缓存 | 32 MiB | 16 MiB |
| SQLite 映射窗口 | 512 MiB | 256 MiB |
| 到期数据渠道并发 | 由独立采集进程负责 | 4 |

两个容器内存上限合计 6.5 GiB，给虚拟机系统、Docker 与文件缓存保留约 1.5 GiB；macOS 和其他应用使用虚拟机之外的内存。映射窗口不是立即把整个数据库装入内存，页缓存则按每条连接分别计费，不能简单设为“每连接几 GB”。文件数据库常驻池限制 2～16、临时池 0～16；非法值回落或夹到边界，内存测试库保留原连接语义。

预热在 API 启动后 2 秒进行，本地视图最多 2 路并行、自选工作区最多 3 路。维护操作串行执行。分析任务、段子分析、下载任务初始并发分别为 2，历史价格读取为 4；只增加处理能力，不增加计划任务数量或自动提交新 AI 任务。数值库每任务单线程，避免多任务各自开启大量 CPU 线程导致前台卡顿。

自选预热覆盖全局标的及已批准用户的自选，股票去重，全局和用户最近加入的标的优先。上限 64 股，对应现有工作区缓存的 128 个总览/详情条目，避免预热把刚准备的首屏数据自行挤掉。只收集股票代码，不输出用户身份，不为待批准账号预热。

配置项均在 [macmini.env.example](../docker/macmini.env.example)，读取入口为 [Mac mini Compose](../docker/docker-compose.macmini.yml)。更小的 VM 必须先降低容器上限；更大机器也应先测量再加并发。`SQLITE_POOL_SIZE`、`SQLITE_MAX_OVERFLOW`、`APP_STARTUP_WARMUP_WORKERS` 与 `WATCHLIST_WORKSPACE_WARMUP_WORKERS` 是部署参数，管理员日常设置页不展示这些调度细节。

## 已取得的证据

### 2026-09-15 Mac mini 真实恢复库

以容器 UID1000 独立进程调用真实服务；SQLite 使用 `mode=ro` / `query_only`，禁止外网、业务写入及后台任务。原文 107,216 条、研报 70,781 条、股票日线 1,534,844 条。检索核对了未分析正文、标题/全文差异和 PDF 链接，并非只检查 HTTP 200。

| 本地服务 | 首次服务读取 | 缓存或翻页读取 |
| --- | --- | --- |
| 华懋自选总览 | 210 ms | 热缓存 5.39 ms |
| 中际自选总览 | 21.77 ms | 热缓存 4.82 ms |
| 首页两股卡片 | 文件页已热时 319 ms | 应用缓存 8 ms |
| 段子“华懋”标题检索 | 77 ms，49 条 | 翻页 45 ms |
| 段子“华懋”全文检索 | 402 ms，158 条 | 翻页 168 ms |
| 研报“低空经济”标题检索 | 41 ms，330 条 | 同口径约 41 ms |

这些是容器内部函数测量，不是本次修改前后对照，不含浏览器和公网往返。操作系统文件页极冷时首页曾为 3.25 秒，仍需预热；真实公网首页一次请求 1.85 秒，不能宣称整站零延时。切换时研报最新为 8 月 30 日、机构资料始于 2025 年 4 月，正在准备独立两年回补；未开启采集的预览行情正确标记陈旧，不冒充最新。

### 较早的本机与离线实验

- 本机真实数据库的只读 ASGI 检查：华懋自选总览冷读取 1.1129 秒，紧接着命中缓存 0.0113 秒；全文检索第一次 3.0561 秒、重复查询 0.2758 秒。它们是同次实验的冷/热差异，**不是本轮改动前后对照，也不是 Mac mini 或公网结果**。响应原文、证券关联和财务字段检查通过，检查进程禁止写数据库、外网和后台任务。
- 临时 SQLite、单股 3,001 条合成证据的首页卡片实验：冷/热中位耗时约 7.61 / 0.63 毫秒；每请求 SQL 从 9 次降至 3 次，其中事件表读取由 6 次降至 0 次。真实数据库大小和访问并发不同，不能把这个耗时宣传为整站响应时间。
- 6 个同时读取同股事实的请求只执行一次事实获取；测试覆盖失败唤醒、后续重试、跨数据库隔离、缓存容量和最新行情立即可见。
- 文件数据库连接池验证：重复读复用连接，超过配置容量不会无限扩张；WAL 写事务未提交时可读取旧已提交值，提交后同一池能读取新值。
- 前端相关 67 项回归、生产构建与 lint 已通过；后端首页/用户隔离/预热 40 项、数据库与部署 97 项、配置注册 54 项通过，合计 258 项。Compose 双层配置已通过真实 CLI 解析。配置解析不启动服务，不替代目标机运行验收。

复现只读业务检查：

```bash
.venv/bin/python -B scripts/readonly_http_acceptance.py \
  --database data/stock_analysis.db --query 华懋 --symbol 603306.SH
```

这个工具仅支持 macOS 的原生只读隔离，测量路由、服务和查询，不测量生产登录、外部网络或后台任务执行。不要直接在现有生产进程内导入该脚本。

## 恢复目标连接后的上线验收

1. 按迁移手册核验最终数据、原账号/会话密钥和新版本构建；生产副本之外保存可恢复备份。
2. 使用 Mac mini 基础 Compose 加 Linux volume 覆盖层，按环境示例设置正式切换开关。确认云端旧采集仍停止，只启一份 API 和一份采集。
3. 验证未登录 `/app` 跳转、已登录用户自选隔离、最新行情与原文读取、下载与后台任务状态；观察采集时间确实推进。
4. 分别记录 Mac mini 回环、家庭局域网和外网的首开、切页与热读取；比较中位数、p95、请求次数、内存、CPU 和网络传输时间。打开行情、检索、AI 和下载时同时测浏览响应。
5. 建议验收目标：已缓存页切换无需等待网络；常用热 API 的服务端 p95 在 150 毫秒内。大规模首次检索与报告生成仍需真实计算，以后台任务和进度展示。公网 RTT、家庭上行、首次资源下载与第三方接口等待无法保证为零。

发现新版本问题时，只回退代码/性能配置，不回退数据库到旧时间点。数据已经在 Mac 上产生新写入后，不能启动旧云数据库接管。
