# 数据一站式获取

“数据一站式获取”把自然语言需求转换为可审计的数据任务，并将不同渠道的结果统一打包。公告、Tushare 和天眼查任务以官方接口现场查询为准；知识星球继续使用 MCP 增量同步后的本地索引。

## 工作流程

页面分为“研报筛选下载”和“跨渠道取数与任务”两个工作区。任务链接直接打开任务区，不需要先滚动通过研报列表；同页切换不丢弃已打开研报库的勾选。

### 人工筛选研报与跨页资料篮

页面上方“研报链接库 · 人工筛选台”只检索已入库的研报元数据。标题和摘要关键词按空格拆分，多个词需同时命中；券商、公司、作者、行业、研报类型、标签、日期、PDF 条件之间也是同时满足。摘要不是 PDF 全文。输入不会立即请求，点击“搜索”或按回车才应用；“重置条件”和日期快捷键也需要再次搜索。

勾选后加入轻量资料篮，翻页和更换搜索条件不会丢失。可以展开“检查已选资料”移除不在当前页的报告，也可清空全部；“全选/取消本页”只操作当前页。一次最多 1,000 篇，选择仅在本页面挂载期间保留，离开页面后清空，不跨账号保存。

“导出已选 N 篇 Excel”只按勾选 ID 导出日期、标题、摘要、类型、券商、作者、公司、代码、行业、标签和 PDF 链接，不自动批量下载 PDF 原文件。原文件可使用每条记录的“打开 PDF”。导出开始时固定本次 ID 列表，之后的勾选变更不会混入正在生成的文件；失败保留选择，可重试。服务端拒绝空选择、超过 1,000 篇或包含已不可用记录的选择，不用空表/部分表冒充完整结果；来源文字以 Excel 文本单元格写入，不作为公式执行。

翻页/搜索失败保留最后成功结果，并提供页内重试，不把接口失败显示成零命中。首次结果和库状态未取得时显示等待/未知，不伪造空库；过期的在途请求不能覆盖较新的结果。页面可见时，空闲每分钟检查库状态，同步进行中每三秒检查；回到标签页立即复查。状态 GET 只读，不再由浏览器启动采集。

现有 `InvestmentMonitorWorker` 每五分钟独立检查研报库，已具备两年覆盖时，距上次同步完成六小时后核对最近14天；即使已有当天研报也会补后续发布。缺少两年覆盖时才按原策略补两年。网页关闭不影响该检查；这不是上游秒级推送，实际新鲜度取决于上游发布时间、任务是否成功和同步间隔，界面显示真实最新研报日期。

Web、采集进程和行业调研唤醒共享数据库中的原子任务租约：运行期间每30秒更新心跳，15分钟无心跳才允许后台接管；`force` 也不得重叠活跃任务。只读查询/构造服务不把其他进程的任务误标中断，失去租约的旧进程不得再写入元数据或任务状态。检索结果仍只在用户提交搜索后更新。

#### 历史恢复与真实断点

研报任务固定本次 `start_date` / `end_date`，按14天窗口、每页1,000条获取元数据和 PDF 链接，不自动下载 PDF，也不触发历史研报 AI 分析。每页数据与下一页 `cursor_offset`、已完成窗口数在同一事务提交；重启后只继续未完成窗口的未完成分页。相同日期范围的失败任务可重试，新的日期范围不会继承旧范围的完成进度。上游超时、无效响应或分页达到安全上限时保留失败状态和断点，不能把未拿到的窗口标成完成。重复页或未变化的记录不算新增/更新。

`POST /api/v1/data-acquisition/research-reports/sync?years=2&force=true` 提交最近两年任务，后台自动检查也会恢复失效租约；失败任务自动重试沿用六小时退避，可由上述接口主动重试，但不能抢占尚存活的采集任务。需要精确恢复固定范围时，服务端使用 `ResearchReportLibraryService.get_instance().start_sync(start_date=date(2024,9,15), end_date=date(2026,9,15), force=True)`，在已有常驻进程中执行，或让进程等待其 Future 完成，不能提交后立刻退出宿主进程。

`GET /api/v1/data-acquisition/research-reports/status` 只读返回目标起止时间、`completed_windows` / `total_windows`、`cursor_offset`、已扫描/实际新增更新数、库内总数/PDF数及最早/最晚研报日期。任务100%表示本次日期窗口已成功遍历，不等于所有券商、所有报告或每一天都有上游可用数据；数据覆盖必须同时核对日期范围、真实行数与上游权限。

### 自然语言跨渠道取数

“后台取数任务”展示当前账号最近任务，点击后按准确任务编号恢复进度与结果。进行中的恢复句柄只存任务编号，并按用户隔离；不沿用旧版全局句柄。切换任务链接不展示迟到的其他任务结果。状态失败保留最近进度，按5/10/20/30秒退避重试；正常每3秒读取，隐藏标签页暂停，返回立即复查。401/403/404停止自动轮询，不重复提交付费/取数任务。

后台提交成功后可离开页面，在当前栏目或“任务与验证”中重新打开。若提交响应丢失，页面提示先检查任务列表，不自动再次执行。生成计划后修改需求必须重新生成并人工核对，避免新文字配上旧计划。首次读取失败、确实空列表和已有快照暂未更新分别展示，各栏目独立重试。

“新建取数任务”只清空当前工作区的所选任务与计划，不取消已提交的后台任务；旧任务暂时读不到时仍可开始新需求，之后从任务列表切回查看。切换任务会清除手动打开的其他数据包预览，避免进度和结果混用。

1. 用户描述股票、日期范围、数据维度和交付口径。
2. 当前配置的规划模型根据能力目录生成最多 12 个任务；服务器立即用股票目录与必要的巨潮官方证券候选核验公司、简称和证券代码，页面展示公司/代码/核验来源及每渠道是否可执行。
3. 唯一可信候选自动补齐代码；重名、无候选、官方检索超时或名称与代码冲突停在计划确认区，不创建后台任务。用户选择候选或填写代码后点击“重新核验”，无需再调用大模型；服务器核验返回可执行后才能确认。任务各自绑定目标，避免多家公司跨渠道串数据。
4. 用户确认后，每个渠道分别接收股票、公司、关键词和日期范围；执行器逐项现场调用 Tushare、巨潮和天眼查，知识星球查询 MCP 增量索引，并对返回数据再次做范围过滤。
5. 运行时单一上游渠道失败不会丢弃其他结果；清单中标记成功、失败、行数和安全错误说明。可预先确定的缺代码错误与此不同，必须在提交前修正。
6. ZIP 按 `tushare/`、`cninfo/`、`zsxq/`、`monitor/`、`tianyancha/` 分目录；每个数据集生成 JSON 与 CSV，每个渠道单独生成 Excel 工作簿，再附 `manifest.json` 和 `README.md`。
7. 用户明确说“下载/文件/附件/PDF/原文文件”时，计划设置 `include_files=true`，公告 PDF、Tushare 可下载研报、知识星球图片附件及结果中的 PDF 会写入 `attachments/` 后一起压缩；未请求时只保留链接。

### 跨渠道现场取数的日期与完成口径

“研报筛选下载”是人工查询本地链接库；“跨渠道取数与任务”的公告与研报执行器每次直接调用官方接口，不能用本地库结果替代本次查询。规划器生成筛选意图，服务器负责复核公司身份、日期范围及渠道参数，不能把模型填写的当天日期当成用户指定范围。

- 用户写“所有/全部公告、研报”且没有明确日期时，`scope.time_range_mode=all_history`，总检索范围为1990年至今；公告按不超过10年的窗口现场分页查询，包含摘要和英文等原先默认排除的公告。研报按官方可提供的2017年起历史查询，精确公司代码可以宽区间分页，不执行数百个空月份请求。范围表示本次向上游请求的边界，不保证上游具备所有年代的全部记录。
- 明确的“近两年”“今天”“昨天”或起止日期优先于“所有”数量词。既没有日期也没有“所有”要求时，公告和研报默认最近两年，并在计划中显示。各子任务日期与范围同步，移除模型遗留的 `trade_date=今天` 等额外单日条件。
- 研报只把官方支持的代码、日期、券商、类型和行业等参数发给接口。标题、摘要、作者等字面条件在召回后做确定性复核，不调用AI删选；“深度”走深度偏好而不是不存在的上游研报类型。返回行还要核验股票身份及日期；公司与主题结合时，无代码行业研报也必须确实提到目标公司，不可仅主题相同就导出。
- 数据集0行记为 `status=failed, outcome=no_data` 并说明实际范围，保留诊断包，不显示“全部成功”。这是未取得数据，不等同于网络故障。上游权限/格式错误独立记录，不吞成空数组。
- 分页重复、扫描/行数上限或附件下载失败必须标为未完整完成；有可用数据的包为 `partial`，无数据为 `failed`。后台100%只表示本次处理已结束，最终说明必须根据实际结果生成。附件失败时元数据依然保留，但不能宣称文件全部取得。
- `manifest.json` 中每个数据集新增 `outcome`、`retrieval` 与 `attachment_error`，记录现场接口、实际范围、分页数、过滤数和是否截断。既有旧任务和数据包保持原样，前端按0行校正显示，不能把旧空包改写成已取得资料。

### 原始文件并行下载与 ZIP 自动续传

服务器下载原始文件最多8路，同一域名最多4路；按原始顺序生成附件清单，去重、HTTPS、PDF头与单文件50MB限制保留。多个渠道共同使用同一500MB/100文件预算，先锁定预留、完成后按真实字节结算，不会因并发突破上限。进度按实际完成/失败文件数推进，单个文件失败不丢掉其余成果。

原始文件遭遇网络断线、超时或408/429/5xx时最多尝试3次。已取得强ETag或Last-Modified时，用Range/If-Range从本次已收到的字节继续；上游不支持续传则从零重新请求，不把完整响应接到半文件后。校验长度、范围与文件标识，确认完整后才写成最终附件。永久错误不重复请求；耗尽尝试仍标失败，不把半文件装包。

浏览器获取已生成ZIP时先通过同一鉴权接口HEAD读取可靠长度、强ETag及Range能力，随后按4MiB分块、最多6路直接从第0块并行启动，不再先串行收完4MiB才启用并发。HEAD最多等待12秒；旧服务不支持HEAD、缺少可靠元数据或探测网络失败时退回首块协商。认证错误不回退GET，明确的错误编码/内容类型也不忽略。单块最多尝试3次，已完成块不重下。每块验证206、Content-Range、Content-Length与同一个强ETag，只有所有字节校验通过才显示100%。鉴权失效、取消、404/416、文件版本变化和错误范围不会盲目重试或混拼。

并发按当前下载中的实际结果调整：浏览器明确开启省流量或报告2G时初始上限2路，其他环境上限6路；网络中断或429/5xx后减少后续请求的许可数，已正常传输的请求不被强行取消，每2个校验通过的分块逐步恢复1路。429/503提供的`Retry-After`以秒数或HTTP日期解析，等待最多30秒。浏览器不支持网络信息API时仍可依靠请求结果调节，不把浏览器类型或猜测的运营商当作测速。

单块每次尝试总上限600秒，另有30秒未增加有效字节的空闲检测；持续收到数据不会再因固定120秒上限过早重下。速度以近5秒有效字节计算，重试回退重设窗口，不把重复收到的半块算成新增；页面最多约每250毫秒更新进度，展示真实速度与预计剩余时间，速度未知时不虚构ETA。下载期间仅暂停本页面30秒一次的空闲列表刷新，进行中后台任务的3秒状态读取不受影响。并发、重试和速度统计只保留在当前内存，不上传网络测速记录。

“浏览器下载”把同源、仍需当前账号授权的成品ZIP交给浏览器原生下载列表；页面只提示移交，不假报100%或已落盘。它不保证比分块更快，但可减少网页Blob缓冲的依赖。普通SPA页面切换后，原分块请求仍可完成并保存；应用检测到退出登录或账号切换使私有会话代际变化时，不保存原账号的迟到结果。此检查不代表会立即终止所有在途字节。刷新、关闭整个标签页或浏览器后，不保证网页分块继续；原生下载能否继续由浏览器决定。

`GET/HEAD /jobs/{job_id}/download` 先检查当前账号权限，再由原生FileResponse提供Range/If-Range和流式读取。ZIP使用identity编码与private/no-store/no-transform，避免全局gzip及中间代理改写字节偏移。匿名/其他用户不能从Range错误响应探知文件大小与ETag。

读取数据包元信息、列出已有包及下载分块时，服务对象不再初始化模型、财经API、巨潮客户端或监控来源注册事务；对应依赖只在实际业务使用时构造并缓存。认证与文件归属校验保留，不用绕过权限换取速度。

续传限于当前这次下载过程：刷新或关闭页面后不持久保留浏览器部分Blob；后台任务与成品ZIP仍保留，可重新下载。此机制不保证所有上游支持续传，也不保证公网带宽或无限重试，不能把功能测试测速当成用户实际网络速度。

## API

- `GET /api/v1/data-acquisition/research-reports/search`：本地人工筛选，`page` / `page_size` 分页，独立标题/摘要/券商/公司等条件。
- `GET /api/v1/data-acquisition/research-reports/facets`：本地可选筛选项。
- `POST /api/v1/data-acquisition/research-reports/export-selected`：`{"ids":[1,31]}`，精确导出勾选研报的 Excel 与 PDF 链接；缺失条目或超限返回错误。
- `GET /api/v1/data-acquisition/capabilities`：数据源、资源和规划器状态。
- `POST /api/v1/data-acquisition/plan`：请求体 `{"request":"..."}`，生成取数计划。
- `POST /api/v1/data-acquisition/validate-plan`：请求体 `{"request":"...","plan":{...}}`，无大模型调用地复核实体、`scope.entity_selections` 与渠道条件，返回规范化计划。`preflight` 是服务器计算的只读结果：`can_execute`、实体候选、逐任务检查和阻断说明；客户端伪造 ready 无效。
- `POST /api/v1/data-acquisition/run`：传入自然语言需求和已确认计划，执行并生成数据包。
- `POST /api/v1/data-acquisition/run-async`：提交后台取数任务，立即返回 `task_id`、真实阶段和初始进度；Web 工作台默认使用此接口。
- 同步执行和异步提交均重新计算前置校验；待确认计划返回400，不创建新数据包或后台任务台账。上游实际取数/文件错误仍按渠道分别记录。
- `GET /api/v1/data-acquisition/tasks/{task_id}`：读取已完成渠道数、当前渠道、导出/压缩阶段和最终数据包结果。任务状态持久化，切换页面后可以继续查看；服务重启中断的任务会明确标记失败，不会永久停在“运行中”。
- `GET /api/v1/data-acquisition/jobs`：最近数据包。
- `GET /api/v1/data-acquisition/jobs/{job_id}/download`：下载 ZIP。

Web 端的取数进度来自服务端已完成任务数和实际导出/压缩阶段，不使用计时器模拟。ZIP 下载进度来自浏览器收到的真实字节数与响应 `Content-Length`；若上游代理未提供总大小，则展示已接收字节数而不伪造百分比。

数据包详情展示各渠道实际行数和失败项；“部分成功”不是全部资料已取得。页面分块一次处理一个数据包，失败时停止动画并保留后台产物，可重新下载。后台打包与浏览器下载是两步：离开页面不影响后台打包；网页下载在同一SPA会话内可继续，刷新/关闭页面不作保证，也可以主动交给浏览器原生下载列表。

新生成的跨渠道数据包中，Excel 的来源文字（含表头与错误说明）明确作为文本写入；CSV 对可能被表格软件解释为公式的字符串添加文本保护。真实数值保持数值，JSON 保留来源原文。该保护只影响新导出，不改写已生成的历史数据包。

### 用户与产物隔离

异步任务提交时捕获请求身份并传入后台线程，包括排队和线程复用；同步执行同样保留当前归属。服务器私有清单记录 `owner_id`，列表先按用户过滤再截取，详情和 ZIP 下载都验证归属。身份字段不返给前端，也不写入 ZIP 内的清单。无归属的旧管理员产物不能作为普通用户共享包。

旧包不直接改写：当后台持久任务台账能以唯一且内部一致的已完成任务证明包的用户归属时，原用户仍可读取/下载；归属冲突、无法确定或当前账号不匹配时拒绝，不猜测所属用户。旧数据文件不删除。

所有文件默认保存在主数据库同级的 `data_acquisition/` 目录。数据包不写入 API Token、OAuth 凭证或天眼查本地认证配置。
